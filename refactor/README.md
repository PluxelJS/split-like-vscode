# Worksplit：FlexLayout 与 TanStack 的工作台集成

状态：讨论稿，尚未实施。更新日期：2026-10-10。

本文是下一轮重构的设计入口，不替代当前 README 或已发布 API。默认行为是推荐设计；多 Router、焦点和内容保留等集成仍需原型验证。本文中的操作名表达语义，不是已经存在的接口。

## 1. 定位与取舍

Worksplit 不再继续自研通用 tab/docking 引擎，也不在 FlexLayout 上重新定义一套布局框架。它提供 **FlexLayout 与 TanStack Router、Store、Hotkeys 的工作台集成**，让应用共享路由标签、焦点、关闭和导航联动，并直接使用上游布局能力。

两个实际消费项目都使用 TanStack Router，重复的工作台接线值得共享。Pluxel 的插件、远程 renderer 和业务服务仍由 Pluxel 负责；第二个应用尚未检查，重构时必须以实际接入验证通用性。

本次提交同步到的上游已加入 `WorkbenchEditingContext`，区分活动编辑组/标签、焦点区域与窗口焦点，并支持空编辑目录。这些现有契约与回归应作为迁移基线复用，不把本文的关注目标设计误读为从零新增，也不只为重构更名。

默认外观以用户选择的 FlexLayout v0.11 demo 为起点，保留 VS Code 风格的工作区与常驻左侧导航，不追求逐像素复刻 VS Code。组合依赖优先，不默认维护上游 fork。

判断一个抽象是否值得加入：去掉它，两个应用是否又要重复实现同一段有生命周期或行为约束的协调逻辑？如果只剩几行上游配置，就保留为配置或示例。

## 2. 沿用原生布局语义

| FlexLayout 概念 | Worksplit 的使用方式 |
| --- | --- |
| Model | 唯一布局事实来源，不建立另一棵可写树 |
| Row | 原生分割结构 |
| TabSet | 原生标签组，拥有组内选择与空间状态 |
| Tab | 独立内容实例，文档和工具共用原生承载 |
| Border | 边缘工具标签条和展开内容 |
| Actions | 原生布局操作，不复刻等价 Action 系统 |
| factory、渲染槽、主题 | 内容与呈现的主要扩展机制 |

应用继续使用原生布局 JSON、类型、主题和适用的渲染槽。Worksplit 不再要求翻译成自己的 WorkspaceLayout、PaneDescriptor 或 PlacementAction。

`editor / primary / secondary / panel` 可以是默认配置里的命名约定，不升级为覆盖原生模型的通用区域系统。默认中央 Tabset、可选左右下 Border；特殊布局仍使用上游表达能力。Border 不等于可任意递归拆分的 Tabset，不承诺抹平两者差别。

Model 由集成实例接纳并管理生命周期，应用可提供初始配置、内容和策略。运行时布局变化从 Model 读取；快照是保存结果，不是另一个编辑源。

## 3. 最佳接入范式

```text
应用的 TanStack 路由定义、内容 renderer、业务回调
                         ↓
          Worksplit 路由标签与会话集成
                         ↓
            FlexLayout Model + Layout
```

最小页面只需常驻导航与中央路由内容。左右下工具、dirty、导航树映射、命令贡献与持久化都可不配置。

应用建立一份路由定义，并通过类型化关联声明或 route metadata 补充工作台信息；具体 API 待类型验证后确定。不要重复维护一套字符串路由表，也不要为了包装将 params/search/navigation 退化为 `string`。

普通 Link/navigate 保留 TanStack 语义。Worksplit 只增加 open/activate/close 等有独立工作台含义的操作，不包办所有 Router API。静态工具使用普通 renderer，无需为了注册工具创建 Router。

先提供一个完整默认组合，不设计多 Router backend、通用插件系统、布局 DSL、消息总线或任意中间件链。特殊需求先使用 renderer、现有原生槽和 React 组合；公共扩展只为实际阻碍增加。

## 4. Worksplit 真正拥有的能力

| 能力 | 边界 |
| --- | --- |
| 路由标签 | 类型化打开、文档去重、标签内导航、浏览器地址协调 |
| 关注与焦点 | 当前文档、工具焦点、激活与关闭后的焦点恢复 |
| 内容生命周期 | dirty 登记、关闭决策与释放协调；保存策略由应用提供 |
| 导航联动 | 当前文档的只读投影；业务资源到导航项的映射由应用提供 |
| 命令接线 | 快捷键、菜单、工具栏共享目标和执行入口 |
| 默认配置与样式 | 原生 Border、主题、常用操作和快捷键；不重写原生标签交互 |

TanStack Store 只保存必要会话事实，不镜像 Model 或完整 Router 状态，不再包装通用 Store API。应用内容可使用自己的状态工具。TanStack Hotkeys 负责按键机制，Worksplit 负责命令目标，不复制上游快捷键解析。

## 5. 内容组合与定制

**只有需要工作台级位置、拖动、关闭或独立恢复的内容，才注册为 FlexLayout Tab。** 是否可枚举不是判断标准。

| 内容 | 推荐方式 |
| --- | --- |
| 文档、设置和业务页面 | 可寻址文档 Tab |
| 独立停靠的 Explorer、Inspector、终端 | 工具 Tab |
| 文件/大纲切换、列表筛选 | 应用的普通 Tabs 或控件 |
| 文档内部主从布局 | 普通 React 布局或现有 Pane Kit |
| 最左侧业务导航、账户、全局命令 | 常驻 shell；入口本身不是空 Tab |
| 菜单、状态栏、临时弹窗 | 内容或 chrome，不加入 docking 树 |

文档和工具共用承载机制，角色不由位置决定：文档移动到边缘仍是文档，工具移动到中央不自动接管 URL。全局工具默认单实例；终端等需要多实例时显式声明。

应用可以提供所有业务内容，并使用主题 tokens、标签装饰、菜单/工具栏贡献和适用的原生渲染槽。先沿用上游槽，仅对真实重复接线增加少量 Worksplit 扩展；不预建全面替换 chrome 的抽象。

自定义呈现必须保留所需 ref、事件和 ARIA 接线，不绕过关闭或停靠规则。第三方表格、编辑器和局部拖放无需转成工作台协议；工作台监听不得无条件吞掉内容事件。跨文档 iframe 焦点需要显式桥接，Portal 弹窗保留发起内容的命令上下文。

单个 renderer 出错只影响该实例。登录、独立展示等非工作台页面由应用在 Worksplit 外组织。

## 6. 原生 Border 与可选工具

已读取指定 demo 的实际 `layouts/default.layout`：左右和底部直接使用 Border，底部包含 Terminal、SubLayout 2、Action Log 和 Layout JSON。配置及源码核对不等于浏览器交互已验收。

底部采用用户偏好的默认行为：有工具时标签条保留，内容可展开、切换或收起。**收起内容、隐藏整个 Border、关闭工具是不同操作。** 无工具时不强留空标签条；全局工具存在时，其入口按声明保留。不要再造重复的底部切换器。

左侧仅用于工具选择时，优先使用原生 Border 标签条；业务导航、账户和命令仍使用常驻 shell。同一工具避免两套等价入口。业务导航与工具选择确有不同用途时可并列呈现。

左右下区域全部可选，纯中央页面无需注册空 pane。全局工具不因某个文档没声明它而消失。用户收起工具后，切换文档不应强行展开或丢失尺寸偏好。

**首轮不实现通用的“每文档一套周边工具布局”编排系统。** 推荐：

- 通用 Explorer/Inspector 作为稳定的全局工具，订阅 active document 并更新内容。
- 页面特有的 pane 或内部 tab 由 renderer 组合，生命周期随页面管理。
- 确有页面级周边工具需求时，再验证原生 Model 能否通过最小配置表达显隐并保留状态，不先建立休眠拓扑、工具停放区或多份布局快照。

如果“只有中央内容”要求连已有全局工具也暂时隐藏，应作为应用明确请求的展示行为，不能从文档缺少声明推断；不得覆盖用户长期显隐偏好。实际接入需要此能力时再定最小接口。

多个编辑组同时可见时，共享 Inspector 跟随 active document。每个组都需要同时显示 Inspector 的情况，用各文档内部 pane 表达。

## 7. 文档地址与身份

| 概念 | 作用 |
| --- | --- |
| 路由定义，如 `/documents/$id` | 匹配内容类型 |
| location，含 search/hash | 当前内容地址 |
| 文档去重键 | 再次打开是否复用 |
| Tab 实例 ID | 持续存在的 UI 实例，也是原生节点身份 |
| Tabset/Border 位置 | 空间放置，不参与业务地址 |

路径驱动内容，不作为布局坐标或所有实例的唯一 ID。移动、pin 不改变文档地址。

默认使用路由身份和规范化 params 去重，search/hash 作为视图状态；影响文档身份的 search 字段由应用显式声明。多实例打开也是显式操作。实现必须处理当前标签导航到已打开文档的冲突：按去重策略定位已有实例，原标签保持原内容，不在提交后静默制造重复文档或丢弃 dirty 内容。细节与 Router blocker 一并原型验证。

## 8. 关注、焦点与 Explorer 联动

区分组内选中标签、active document、实际 DOM 焦点与命令目标。Model 提供活动组、选中节点和变更订阅；不复制其可直接派生的状态。最近的 active document 是必要的会话引用，因为用户可以把焦点移到工具。

```text
用户激活文档 / 聚焦文档内容 / 提交文档导航
  → Model 选择 + 文档身份 + 已提交 location
  → active document
  → 浏览器地址、导航归属高亮、Explorer 文档标记
```

模型订阅覆盖程序操作；内容焦点进入同一激活路径。后台导航或较早完成的请求不能抢占关注目标。

工具、菜单和弹窗获得焦点不清空 active document，也不替换文档 URL。保存命令以活动文档为目标，工具命令以工具上下文为目标，不能把所有命令都转发给文档。

应用按需提供导航归属或资源 key，Worksplit 提供类型化只读订阅。区分文档归属高亮、当前显示的工具、树内键盘焦点：文档变化默认只更新归属标记，不切走搜索、不打开隐藏 Explorer、不抢树焦点。自动展开/滚动定位可由 Explorer 显式提供，局部树行为不进入工作台状态机。

用户点击导航项触发 open/activate；派生高亮不得反向触发导航。没有匹配导航项时清空文档标记，不选择任意兜底节点。

激活内容时恢复合理焦点，编辑器/终端可提供显式 focus 回调。关闭活动文档优先选同组最近使用文档，再选其他组最近使用文档，最后进入应用声明的工作台首页。关闭后台文档不切焦点。

## 9. Router 与浏览器历史

多组可以同时显示不同 location，浏览器只有一个 URL。不能复制同一 Router 的普通 Outlet 来获得独立标签上下文。

候选路线是每个路由文档实例持有独立 Router/memory history，Worksplit 统一协调浏览器 history。必须先验证原生 hooks、Outlet、loader、redirect、context、错误边界、路由对象复用和类型推导；尚未证明可用，不将此候选写成既有能力。

| 操作 | 推荐历史行为 |
| --- | --- |
| 新文档或当前文档导航到新地址 | 提交后 push，保留显式 replace 的原义 |
| 切换已有标签、聚焦另一文档组 | replace，不堆积焦点记录 |
| 相同规范化 location | 不新增记录 |
| resize、pin、工具切换 | 不写入；若激活另一文档，仅按激活规则 replace |
| 关闭活动文档 | 选定后继后 replace |
| 前进/后退 | 消费历史目标，不再次 push |
| 后台文档导航 | 不写浏览器地址，激活时同步 |

replace 会覆盖当前历史位置的文档，这是明确取舍；浏览器后退不承诺恢复每次标签焦点。首轮不另造跨标签历史系统或标签 back/forward UI。

历史指向已关闭文档时按地址新开，不恢复已丢弃草稿。history state 可以保存仍存活实例的定位提示，但 URL 本身足以普通深链接。刷新验证快照后以地址栏确定活动目标。

文档内普通 Link/navigate 默认在当前标签导航；导航树 open 默认复用文档或新建标签。外链、下载和浏览器新窗口行为保留。导航被拒绝时不得发布成功结果；popstate、异步关闭和竞争导航时如何保持 Model、URL、Router 一致，是原型必须验证的提交边界。

## 10. 受控操作与停靠策略

沿用原生语义不等于允许绕过工作台契约。运行时 Model 由集成层持有；应用配置原生模型，通过只读查询了解状态，通过受控入口提交操作。原生 TypeScript Model 本身可写，因此不能仅靠给它命名为只读就保证安全；普通公共入口不直接暴露其可变对象。

打开、关闭和路由导航使用 Worksplit 语义入口；纯布局操作可提交原生 Action，由集成层按需验证并调用 Model。UI 操作同样进入这一边界。不要定义一套与 Actions 一一对应的新操作类型。

需要严格限制停靠时，应用提供针对原生节点/目标及文档元数据的纯策略。拖动预览、实际提交、程序操作和恢复使用同一规则；整组移动检查全部成员。默认配置可限制文档在中央、工具在指定 Border，不强迫所有应用使用相同规则。

策略只解决真实约束，不预建通用策略语言或全局事务引擎。上游拖放 Hook 不足以保证所有入口；如果所需约束只能靠内部 patch 或复制布局算法实现，应先重新评估需求和上游扩展点。

## 11. 生命周期、命令和保存

普通内容无需 dirty 或异步关闭协议，默认直接关闭。有需要时应用提供关闭决策；鼠标、快捷键和程序关闭都经过同一入口。关闭确认期间实例仍有效，被拒绝时不移除节点。获准后协调移除、订阅撤销、资源释放和后继焦点。

切换、移动、pin 和收起默认保留内容实例。隐藏不等于暂停后台任务，激活状态由内容按需消费。文档内部路由变化保留 Tab 实例，但旧路由内容依 Router 生命周期退出，不能跳过 dirty 离开拦截。

快捷键、菜单和工具栏复用命令。隐藏但挂载的内容不能同时响应全局保存；输入框、编辑器和弹窗的事件处理应被尊重。内容局部操作无需全部注册为工作台命令。

持久化可选，不默认写全局 localStorage。应用启用时提供存储接线与工作区标识，Worksplit 序列化原生布局及必要会话数据。业务缓存、凭据、草稿和任意 React 状态不自动打包；派生高亮恢复后重新计算。

不兼容快照明确报告，提供显式重置或转换，不静默挪动标签伪装成功。应用撤回动态内容时，新打开失效，旧实例明确显示不可用并释放失效资源；草稿恢复由应用决定，不强造通用插件生命周期框架。

## 12. 实施顺序与验收

先用两个并排路由标签验证路由与焦点主路径，再扩展原生 Border、pin、关闭与应用接入。每一步都应删除已有重复接线，而不是增加新旧同步层。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 简单页面 | 常驻导航与中央内容即可工作，无空 pane 或存储前提 |
| 两个路由文档 | params/search、loader 与内容独立，焦点决定地址 |
| Explorer 联动 | 更新归属高亮，不抢工具选择/树焦点，无导航循环 |
| 底部 Border | 内容收起保留标签条，无可用工具不留空条 |
| 原生槽和普通 Tabs | 能定制内容，无额外布局节点，键盘/拖动仍正确 |
| 移动、pin、最大化、收起 | 状态和资源保留，不重新实现原生标签系统 |
| dirty 关闭和导航 | 拒绝后保留原实例；所有入口一致 |
| 前进后退、异步竞争、去重冲突 | URL 与已提交文档一致，不抢回焦点或丢失内容 |
| 受限拖放、程序 Action、恢复 | 相同策略在所有入口生效 |
| 内容错误 | 仅影响该实例，不重建工作台 |
| 两个应用接入 | 无 Pluxel 专属依赖，能删除重复控制器代码 |

首轮使用原生 pin 和核心键盘能力，补工作台焦点协调；不引入 preview 自动替换、复杂快捷键编辑器、通用上下文工具编排或多窗口协议。窄屏保留常驻导航与可用内容切换，不覆盖桌面偏好，具体呈现待验证。

迁移后删除被替代的 editor arrangement、DnD 和拓扑实现；基础 SplitView 按 Pane Kit 等真实用途决定。旧快照只做必要的一次性转换或明确重置，不长期保留双引擎与兼容读取链。

当前仅完成设计和部分上游源码/配置核对，未实施、未完成浏览器或消费应用验收。决定路线前最关键的证据是多 Router 集成、原生内容保留、受控 Action 边界及两个真实应用的接入成本。
