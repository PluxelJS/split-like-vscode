# Worksplit：FlexLayout 与 TanStack 的工作台集成

状态：内部重构及原生 FlexLayout 能力接入已完成检查、浏览器验收与测量；实际通过范围见 [acceptance.md](acceptance.md)。更新日期：2026-10-11。

本页保留原设计目标及迁移归属；当前 API 和实际行为分别由 [README](../README.md) 与 [行为契约](../docs/vscode-workbench-behavior.md) 维护。实现调整：去重保证限定在 open；原生导航的最终身份冲突明确报告并保留实例；文档创建、身份和生命周期由集成协调，普通分组、呈现属性与纯布局批次沿用原生 Actions；整组关闭与纯关闭批次经过文档决策；禁用 float/popout/sublayout；待决 history traversal 期间新 open 明确拒绝；外部历史项交由宿主。没有复制 Router 流水线或维护上游 fork。

本文记录本轮重构的设计目标、推荐行为与实施顺序，不替代[当前用法](../README.md)。下文推荐行为保留设计讨论语义，实际通过范围与收窄项以[验收记录](acceptance.md)及行为契约为准；操作名不是另一套公共接口签名。

原型路线门槛（已通过，证据见验收记录）：**两个并排路由文档、一个全局工具、dirty 拦截，以及慢导航与浏览器后退场景。** 先证明路由、内容生命周期与受控操作能组合，再确定公共 API、持久化格式和迁移方案。

实施范围：先在 Worksplit 独立分支完成库、内部 demo、测试与用法更新，内部消费必须通过公开包入口。**本轮不迁移 Pluxel，也不更新 Pluxel 的子模块指针或依赖。** Worksplit 内部重构验收完成后，再另行接入 Pluxel 和第二应用。内部验收完成不等于跨应用通用性已经验证。

## 1. 定位与取舍

Worksplit 不再继续自研通用 tab/docking 引擎，也不在 FlexLayout 上重新定义一套布局框架。它提供 **FlexLayout 与 TanStack Router、Store、Hotkeys 的工作台集成**，让应用共享路由标签、焦点、关闭和导航联动，并直接使用上游布局能力。

两个实际消费项目都使用 TanStack Router，重复的工作台接线值得共享。Pluxel 的插件身份、远程 renderer、RPC 和业务服务仍由 Pluxel 负责。第二个应用尚未检查，不能只凭技术栈相同认定需求相同。本轮先用内部 demo 收敛可用 API；跨应用适用性留到后续实际接入验证，不为尚未检查的消费者预建扩展。

当前 Pluxel 的消费代码提供了三个具体迁移验收对象：

- `WorkbenchDocumentRenderer.tsx` 手工按 pathname 分发页面；新集成应消除重复页面匹配。
- `WorkbenchShell.tsx` 与 `WorkspaceEditorGrid.tsx` 分别处理关闭确认和活动标签的地址同步；这些协调应有一个所有者。
- `split/view.tsx` 对接旧 Worksplit 布局协议；迁移时区分随旧协议删除的转换与仍服务独立 Pane Kit 的能力。

这些文件位于 Pluxel 的 `packages/workbench/shell/src/app/workbench/`，只是实际消费证据，不成为 Worksplit 的依赖。

重构基线 `e607932` 已有 `WorkbenchEditingContext`、活动编辑组/标签与焦点区域/窗口焦点的区分，并支持空编辑目录。新版保留名称和这些必要行为；实际字段与回归以当前用法及验收记录为准。

默认外观以用户选择的 FlexLayout v0.11 demo 为起点，保留 VS Code 风格的工作区与常驻左侧导航，不追求逐像素复刻 VS Code。组合依赖优先，不默认维护上游 fork。

判断一个抽象是否值得加入：去掉它，两个应用是否又要重复实现同一段有生命周期或行为约束的协调逻辑？如果只剩几行上游配置，就保留为配置或示例。

## 2. 沿用原生布局语义

| FlexLayout 概念       | Worksplit 的使用方式                 |
| --------------------- | ------------------------------------ |
| Model                 | 唯一布局事实来源，不建立另一棵可写树 |
| Row                   | 原生分割结构                         |
| TabSet                | 原生标签组，拥有组内选择与空间状态   |
| TabGroup              | 标签栏中的可命名、着色与折叠分组     |
| Tab                   | 独立内容实例，文档和工具共用原生承载 |
| Border                | 边缘工具标签条和展开内容             |
| Actions               | 原生布局操作，不复刻等价 Action 系统 |
| factory、渲染槽、主题 | 内容与呈现的主要扩展机制             |

应用继续使用原生布局 JSON、类型、主题和适用的渲染槽。Worksplit 不再要求翻译成自己的 WorkspaceLayout、PaneDescriptor 或 PlacementAction。
外部宿主可省略内置导航并拥有完整外壳；binding 透传根 DOM 属性与原生 `ILayoutApi` ref，不增加 handle、主题或内容工厂协议。每文档 provider 使用 Router 的 Wrap/InnerWrap，工具复用普通 React 组件。工具注册只拥有 id/renderer，标题、大小和停靠选项由原生 JSON 拥有。已登记工具可用单次原生 ADD_TAB 重新入树；入树回执、ref 拦截限制和 allowDrop 限制维护在 [公开用法](../README.md#customize-the-host-with-native-apis)。
React/TanStack/FlexLayout 适配器由宿主以 peer 提供；快捷键偏好与业务 Store 使用原生 SDK，运行时改键通过原生 hook 调用公开命令，无第二套键盘或数据状态协议。具体用法维护在 [宿主快捷键与 Store](../README.md#host-shortcuts-and-frontend-stores)。

`editor / primary / secondary / panel` 可以是默认配置里的命名约定，不升级为覆盖原生模型的通用区域系统。默认中央 Tabset、可选左右下 Border；特殊布局仍使用上游表达能力。Border 不等于可任意递归拆分的 Tabset，不承诺抹平两者差别。
空中央分区遵循 FlexLayout 默认清理；最后一个空 root 由原生 tidy 保留。不能为了空编辑目录而全局关闭 `tabSetEnableDeleteWhenEmpty`，否则每次搬空来源都会留下空分区。分区 ID 随原生整理变化，不把 `left/right/main` 当成永久区域；确需固定空空间时由应用对指定 TabSet 显式配置。

原生 JSON 的缺省 children、上下文根节点/Border 类型、tab 类型及文档自动 ID 保持可用；明确非法字段仍拒绝。内容外层不截断原生滚动，属性重置沿用原生运行时行为，不另造 Action 类型。内容错误直接使用 FlexLayout 的单标签错误边界与 Retry；Router 错误由 TanStack 处理。Layout 由原生更新驱动，binding 不订阅文档目录 revision，保留 adjusting resize 的上游路径。
Dock 面向有足够视口空间的桌面工作台，不按屏幕英寸划定支持范围。缩小窗口不自动最大化、不插入文档切换器，也不维护桌面偏好覆盖层；快照保存实际原生 Model。应用可用原生 Actions 和控件明确选择最大化，导航样式由应用负责；本轮验证缩小窗口后的布局、输入和资源保留，不强制手机或触屏停靠兼容。

Model 由集成实例接纳并管理生命周期，应用可提供初始配置、内容和策略。运行时布局变化从 Model 读取；快照是保存结果，不是另一个编辑源。

## 3. 最佳接入范式

```text
应用的 TanStack 路由定义、内容 renderer、业务回调
                         ↓
          Worksplit 路由标签与会话集成
                         ↓
            FlexLayout Model + Layout
```

最小页面只需常驻导航与中央路由内容。左右下工具、dirty、导航树映射、命令贡献与持久化都可不配置。

应用建立一份路由定义，并通过类型化关联声明或 route metadata 补充工作台信息；类型验证已完成，实际 API 见当前用法。不要重复维护一套字符串路由表，也不要为了包装将 params/search/navigation 退化为 `string`。

普通 Link/navigate 保留 TanStack 语义。Worksplit 只增加 open/activate/close 等有独立工作台含义的操作，不包办所有 Router API。静态工具使用普通 renderer，无需为了注册工具创建 Router。

先提供一个完整默认组合，不设计多 Router backend、通用插件系统、布局 DSL、消息总线或任意中间件链。特殊需求先使用 renderer、现有原生槽和 React 组合；公共扩展只为实际阻碍增加。

实现先保持一个集成实例，内部按布局接线、文档会话和浏览器历史协调拆模块。这是职责划分，不要求三个公共控制器或新包；现有包边界按真实依赖调整。行为验收条目不自动对应一个公开接口、类或协议。

## 4. 能力、状态与资源所有权

| 能力           | 边界                                                    |
| -------------- | ------------------------------------------------------- |
| 路由标签       | 类型化打开、文档去重、标签内导航、浏览器地址协调        |
| 关注与焦点     | 当前文档、工具焦点、激活与关闭后的焦点恢复              |
| 内容生命周期   | dirty 登记、关闭决策与释放协调；保存策略由应用提供      |
| 导航联动       | 当前文档的只读投影；业务资源到导航项的映射由应用提供    |
| 命令接线       | 快捷键、菜单、工具栏共享目标和执行入口                  |
| 默认配置与样式 | 原生 Border、主题、常用操作和快捷键；不重写原生标签交互 |

TanStack Store 只保存必要会话事实，不镜像 Model 或完整 Router 状态，不再包装通用 Store API。应用内容可使用自己的状态工具。TanStack Hotkeys 负责按键机制，Worksplit 负责命令目标，不复制上游快捷键解析。

| 事实或资源                               | 权威所有者                   | 集成边界                                     |
| ---------------------------------------- | ---------------------------- | -------------------------------------------- |
| 布局树、位置、组内选中、尺寸、pin        | FlexLayout Model             | 由集成实例持有，不维护第二棵可写树           |
| 已提交 location、匹配结果与路由加载状态  | 对应文档 Router              | Worksplit 协调提交，不镜像完整 Router store  |
| Tab 实例及其 Router、订阅和内容寿命      | Worksplit 集成实例           | 创建、接纳、关闭与释放；失败创建不得遗留资源 |
| 最近活动文档、文档 MRU、进行中的协调操作 | Worksplit 会话               | 只保存不能从 Model/Router 直接派生的事实     |
| 文档去重键                               | 路由身份声明及已提交路由数据 | 由集成生成索引，不让应用重复拼接内部 key     |
| DOM 焦点与窗口焦点                       | 浏览器                       | 观察并协调，不以选中标签冒充实际焦点         |
| 浏览器地址与历史                         | 浏览器 history               | 工作台范围内只有一处写入协调，消费 popstate  |
| dirty、关闭/离开决策                     | 应用内容                     | 登记当前事实，不推断业务是否已保存           |
| 登录态、业务服务、共享缓存、草稿         | 应用                         | 文档实例借用，不随标签关闭共享资源           |
| 布局快照                                 | 持久化输出                   | 校验与恢复，不作为运行时第二个编辑源         |

所有权表用于审查实现：可直接派生的状态不重复写入；无法直接派生的会话事实必须有明确更新与释放边界。资源成本和完成阶段见第 11 节。

## 5. 内容组合与定制

**只有需要工作台级位置、拖动、关闭或独立恢复的内容，才注册为 FlexLayout Tab。** 是否可枚举不是判断标准。

| 内容                                 | 推荐方式                         |
| ------------------------------------ | -------------------------------- |
| 文档、设置和业务页面                 | 可寻址文档 Tab                   |
| 独立停靠的 Explorer、Inspector、终端 | 工具 Tab                         |
| 文件/大纲切换、列表筛选              | 应用的普通 Tabs 或控件           |
| 文档内部主从布局                     | 普通 React 布局或现有 Pane Kit   |
| 最左侧业务导航、账户、全局命令       | 常驻 shell；入口本身不是空 Tab   |
| 菜单、状态栏、临时弹窗               | 内容或 chrome，不加入 docking 树 |

文档和工具共用承载机制，角色不由位置决定：文档移动到边缘仍是文档，工具移动到中央不自动接管 URL。全局工具默认单实例；终端等需要多实例时显式声明。

应用可以提供所有业务内容，并使用主题 tokens、标签装饰、菜单/工具栏贡献和适用的原生渲染槽。先沿用上游槽，仅对真实重复接线增加少量 Worksplit 扩展；不预建全面替换 chrome 的抽象。原生槽可能暴露可变对象，开放范围与使用约束见第 10 节，不能承诺透传所有槽且同时完全隔离 Model。

自定义呈现必须保留所需 ref、事件和 ARIA 接线，不绕过关闭或停靠规则。第三方表格、编辑器和局部拖放无需转成工作台协议；工作台监听不得无条件吞掉内容事件。跨文档 iframe 焦点需要显式桥接，Portal 弹窗保留发起内容的命令上下文。

单个 renderer 出错只影响该实例。登录、独立展示等非工作台页面由应用在 Worksplit 外组织。

## 6. 原生 Border 与可选工具

已读取指定 demo 的实际 `layouts/default.layout`：左右和底部直接使用 Border，底部包含 Terminal、SubLayout 2、Action Log 和 Layout JSON。配置及源码核对不等于浏览器交互已验收。

内部 demo 用公开工具注册与原生 `location: "right"` 配置右侧 Details，保留底部 Inspector；侧栏入口、展开、收起、尺寸与停靠继续归 FlexLayout。具体用法见 [README](../README.md)，实际通过范围和截图见 [验收记录](acceptance.md)。

底部采用用户偏好的默认行为：有工具时标签条保留，内容可展开、切换或收起。**收起内容、隐藏整个 Border、关闭工具是不同操作。** 无工具时不强留空标签条；全局工具存在时，其入口按声明保留。不要再造重复的底部切换器。

左侧仅用于工具选择时，优先使用原生 Border 标签条；业务导航、账户和命令仍使用常驻 shell。同一工具避免两套等价入口。业务导航与工具选择确有不同用途时可并列呈现。

左右下区域全部可选，纯中央页面无需注册空 pane。全局工具不因某个文档没声明它而消失。用户收起工具后，切换文档不应强行展开或丢失尺寸偏好。

**首轮不实现通用的“每文档一套周边工具布局”编排系统。** 推荐：

- 通用 Explorer/Inspector 作为稳定的全局工具，订阅 active document 并更新内容。
- 页面特有的 pane 或内部 tab 由 renderer 组合，生命周期随页面管理。
- 确有页面级周边工具需求时，再验证原生 Model 能否通过最小配置表达显隐并保留状态，不先建立休眠拓扑、工具停放区或多份布局快照。

如果“只有中央内容”要求连已有全局工具也暂时隐藏，应作为应用明确请求的展示行为，不能从文档缺少声明推断；不得覆盖用户长期显隐偏好。实际接入需要此能力时再定最小接口。

多个编辑组同时可见时，共享 Inspector 跟随 active document。每个组都需要同时显示 Inspector 的情况，用各文档内部 pane 表达。

## 7. 文档地址与身份

| 概念                          | 作用                                 |
| ----------------------------- | ------------------------------------ |
| 路由定义，如 `/documents/$id` | 匹配内容类型                         |
| location，含 search/hash      | 当前内容地址                         |
| 文档去重键                    | 再次打开是否复用                     |
| Tab 实例 ID                   | 持续存在的 UI 实例，也是原生节点身份 |
| Tabset/Border 位置            | 空间放置，不参与业务地址             |

路径驱动内容，不作为布局坐标或所有实例的唯一 ID。移动、pin 不改变文档地址。

默认使用路由身份和规范化 params 去重，search/hash 作为视图状态；影响文档身份的 search 字段由应用显式声明。规范化遵循路由解析契约，不能自行排序或丢弃有业务意义的数据。多实例打开必须显式请求。

普通 open 匹配到多个显式多实例时，优先复用当前活动的匹配实例，其次选择最近使用的匹配实例；尚无使用记录时使用稳定的创建顺序。业务要求特定实例时显式指定目标，不让布局位置参与文档身份。

按已有实例 ID 激活只切换关注，保留其 search/hash；提交完整路由目标的 open/navigate 表示请求该地址，不能悄悄忽略 search/hash。导航树若只想定位已打开文档，应在找到实例后激活它；未打开时才提交默认地址。这两种意图保持显式，不增加含糊的隐式重置规则。

去重决定目标实例，不等于忽略目标地址。当前标签请求导航到已打开文档时，原标签保持原内容，已有实例接受所请求的 location；需要改变已有实例路由时，遵守该实例的离开决策。redirect、并发打开及提交边界见第 9 节，不在提交后静默制造重复文档或丢弃 dirty 内容。

## 8. 关注、焦点与 Explorer 联动

区分组内选中标签、active document、实际 DOM 焦点与命令目标。Model 提供活动组、选中节点和变更订阅；不复制其可直接派生的状态。最近的 active document 是必要的会话引用，因为用户可以把焦点移到工具。

```text
用户激活文档 / 聚焦文档内容 / 提交有效的前台文档导航
  → Model 选择 + 文档身份 + 已提交 location
  → active document
  → 浏览器地址、导航归属高亮、Explorer 文档标记
```

模型订阅覆盖程序操作；内容焦点进入同一激活路径。后台导航或较早完成的请求不能抢占关注目标。

工具、菜单和弹窗获得焦点不清空 active document，也不替换文档 URL。保存命令以活动文档为目标，工具命令以工具上下文为目标，不能把所有命令都转发给文档。

应用按需提供导航归属或资源 key，Worksplit 提供类型化只读订阅。区分文档归属高亮、当前显示的工具、树内键盘焦点：文档变化默认只更新归属标记，不切走搜索、不打开隐藏 Explorer、不抢树焦点。自动展开/滚动定位可由 Explorer 显式提供，局部树行为不进入工作台状态机。

用户点击导航项触发 open/activate；派生高亮不得反向触发导航。没有匹配导航项时清空文档标记，不选择任意兜底节点。

激活内容时恢复合理焦点，编辑器/终端可提供显式 focus 回调。关闭后的后继与异步焦点规则由第 11 节统一维护。

## 9. Router 与浏览器历史

### 9.1 实例与导航上下文

多组可以同时显示不同 location，浏览器只有一个 URL。不能复制同一 Router 的普通 Outlet 来获得独立标签上下文。

实际路线是每个路由文档实例持有独立 Router/memory history，Worksplit 统一协调浏览器 history。已在锁定版本上验证共享同一批运行时路由对象，证据见验收记录；不延伸为任意 Router 版本的保证。

原型使用真实嵌套路由，验证原生 hooks、Outlet、params/search、loader、redirect、context、错误边界、blocker 和类型推导，不用手写 pathname 分发或自行复制 loader 逻辑代替。

应用提供共享登录态、服务与缓存，文档 Router 借用；文档专属上下文与 Router 随 Tab 释放。实测多个 Router 是否重复加载、预加载或重复建立订阅，再决定接线，不提前设计全局路由缓存。

文档内普通 Link/navigate 默认在当前标签导航，保留相对导航及显式 replace 的原义；常驻导航的文档入口使用类型化 open，默认复用或新建。外链、下载和修饰键打开新窗口等浏览器行为保留。应用外层 Router 与工作台 history 的职责必须明确，不能同时响应同一目标并各自提交。非工作台页面仍由应用路由处理。

### 9.2 导航何时算提交

推荐协调顺序：确定目标实例和规范化地址 → 检查去重及适用的离开决策 → 执行 Router 导航 → 复核实例有效性、操作是否被取代及最终身份 → 发布已提交结果。redirect 后的最终目标也必须接受冲突检查。

提交后，Router 已接受的 location、文档身份索引和该操作所需的 Model 选择一致；仅当文档仍是应发布的活动目标时同步浏览器地址和导航投影。这是协调目标，不宣称 Router、Model 与浏览器之间已有原子事务。最终身份检查能否发生在破坏原内容之前，是原型必须证明的条件。

loader 报错不自动等于导航拒绝：若 Router 接受新 location 并显示其错误边界，应按已提交错误页面处理。blocker 拒绝则保留原内容和已提交地址。必须核对真实完成信号，不能只凭 `navigate()` Promise 完成认定整个工作台协调成功。

| 场景                                            | 推荐结果                                                                                   |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------ |
| A 请求导航到已打开的 B，目标 location 与 B 相同 | 激活 B，A 保持原内容；A 未离开时不触发其丢弃确认                                           |
| B 与请求的 search/hash 不同，但去重键相同       | 在 B 上执行目标地址导航，获准提交后按前台意图激活；拒绝时保留原活动目标，不忽略请求地址    |
| redirect 后才发现目标已打开                     | 同样去重，不先覆盖 A 再静默合并；提交前协调能力需验证                                      |
| 两个普通 open 并发打开同一文档                  | 提交时保证去重唯一性；复用被接纳实例，释放未接纳实例的资源；显式多实例请求不受此唯一性限制 |
| 同一实例先后导航到 B、C                         | 后续操作取代前序操作，B 的晚到结果不能覆盖 C                                               |
| A 慢导航期间用户激活 B                          | A 可完成仍有效的后台导航，但不能抢回活动目标与 URL                                         |
| 导航期间实例被关闭或撤回                        | 晚到结果不重建实例或写入地址，按实际阶段结算                                               |

焦点变化与同一实例的新导航是不同事件：前者撤销抢占活动目标的资格，后者使旧导航失效。底层无法取消的工作可能继续，不能把忽略结果宣称为实际取消。

redirect 后去重且保留原内容是首个可行性试验。如果必须复制 Router 导航流水线、维护第二套匹配结果或修改上游内部才能保证，先依据证据修订该推荐语义，例如收窄去重发生的入口或明确拒绝无法协调的冲突。修订必须更新文档、测试和示例，并说明行为差异；不得静默丢内容、宣称支持未支持的导航，也不为保住讨论稿而再造 Router。

工作台操作需要区分已提交、被决策拒绝、被后续操作取代和执行失败，具体结果类型由原型确定。保留原生 Router 错误与原因；失败反馈包含目标、阶段及已发生的影响，不将拒绝包装成成功，也不为协调引入通用事务框架。

### 9.3 浏览器历史

| 操作                         | 推荐历史行为                                 |
| ---------------------------- | -------------------------------------------- |
| 新文档或当前文档导航到新地址 | 提交后 push，保留显式 replace 的原义         |
| 切换已有标签、聚焦另一文档组 | replace，不堆积焦点记录                      |
| 相同规范化 location          | 不新增记录                                   |
| resize、pin、工具切换        | 不写入；若激活另一文档，仅按激活规则 replace |
| 关闭活动文档                 | 选定后继后 replace                           |
| 前进/后退                    | 消费历史目标，不再次 push                    |
| 后台文档导航                 | 不写浏览器地址，激活时同步                   |

replace 会覆盖当前历史位置的文档，这是明确取舍；浏览器后退不承诺恢复每次标签焦点。首轮不另造跨标签历史系统或标签 back/forward UI。

历史指向已关闭文档时按地址新开，不恢复已丢弃草稿。history state 可以保存仍存活实例的定位提示，但 URL 本身足以普通深链接；提示失效时不能误认另一个实例。刷新验证快照后以地址栏确定活动目标。

popstate 发生时地址栏可能已经变化。若导航被拒绝，必须恢复上一个接受的位置，不制造新历史项或循环；快速连续后退、前进及待决确认期间的新导航均需实测。**不能可靠协调拒绝与恢复时，暂停公共 API 定型并调整路线。** 不以最后一次 replace 掩盖历史栈已被破坏。

## 10. 受控操作与停靠策略

沿用原生语义不等于允许绕过工作台契约。运行时 Model 由集成层持有；应用配置原生模型，通过查询了解状态，通过受控入口提交操作。普通业务 renderer 只获得必要内容信息与工作台操作，不直接获得可变 Model；TypeScript `Readonly` 不构成运行时隔离。

原生 factory、部分渲染槽及 Layout ref 可能提供节点或其他上游对象。实施前追踪它们及子引用是否可访问可变 Model，不能只检查顶层返回值。推荐区分普通业务 renderer 与高级原生呈现扩展：前者提供窄能力，后者仅开放已核对、可遵守协调契约的槽。

若必须透传完整原生对象，明确该入口属于应用可信扩展，禁止直接修改集成拥有的 Model，并说明这是使用约束而非运行时强制保证。是否接受这一边界由原型与真实调用决定，不默认包装整套上游节点 API 来制造隔离表象。

打开、关闭和路由导航使用 Worksplit 语义入口；纯布局操作可提交原生 Action，由集成层验证并调用 Model。UI 操作同样进入这一边界，不定义一套与 Actions 一一对应的新操作类型。按实际效果分类 Action：可能移除文档、改写受保护身份或绕过关闭决策的操作，不能当作无害布局操作放行。

应用直接从 `flexlayout-react` 导入 Actions、JSON 类型和菜单 helpers。集成只接管 Model、factory、Action 提交及文档生命周期所需入口；适用的原生呈现与交互属性继续使用 `ILayoutProps`。不为分组、颜色、折叠、尺寸或菜单另建公共协议。原生 `onModelChange` 是可信只读观察入口，不能借它替换或改写 Model。上游 `useUndo` 会替换整个 Model、可能恢复已释放的文档，不属于普通布局操作。

原生 `Actions.group` 改变中央选择或显式选择中央文档/active TabSet 时，文档激活和 URL 依据最终中央选中文档协调，不逐步推断跨空间焦点意图或复制 Model 流水线。仅选择 Border/工具且中央选择未变的批次保留最后文档。单条 `Actions.selectTab` 可显式激活 Border 文档；工具选择与 Border 收起仍保留文档 URL。移动活动文档且原生仍选中它时保留 URL；整组移入 Border 遵循上游原有选择，不强制显示移动成员。原生选择及键盘操作拥有 DOM 焦点，集成不调用内容 focus；显式 open/activate 的排队焦点恢复受最新选择与焦点的 epoch 约束。React binding 捕获 `native.onModelChange` 异常并通过 `onIssue` 报告；其他原生 Model/Node observer 属于可信上游代码，不提供 sandbox 或回滚。
上述最终中央投影只用于多操作批次；只有一个叶 Action（含嵌套）的原生 GROUP 沿用该单操作的文档选择/移动语义，Model 仍执行原批次、observer 仍接收原 GROUP。无需复制多步流水线来制造单操作差异。

需要严格限制停靠时，应用提供针对原生节点/目标及文档元数据的纯策略。拖动预览、实际提交、程序操作和恢复使用同一规则；整组移动检查全部成员。默认配置可限制文档在中央、工具在指定 Border，不强迫所有应用使用相同规则。

策略只解决真实约束，不预建通用策略语言或全局事务引擎。原型列出 UI、快捷键、程序 Action、整组操作和恢复的实际接入点；单个拖放 Hook 不足以保证所有入口。若所需约束只能靠内部 patch 或复制布局算法实现，应先重新评估需求和上游扩展点；无法协调的入口明确收窄或禁用，不静默建立 fork。

锁定 0.11.1 的 `setOnAllowDrop` 只覆盖拖放预览，程序 move 由集成复核；原生 `Actions.group` 的子操作没有公开的逐步 veto hook。有应用停靠策略时，包含移动或分组的多步纯布局批次明确拒绝，调用方逐次提交；无该策略的纯布局批次沿用原生执行。混合布局与关闭的批次也明确拒绝，以免决策拒绝后留下部分布局效果。纯关闭批次先取得全部有效决策，再用原生 Actions 移除；不复制布局流水线或创建用于模拟的 Model。

## 11. 生命周期、命令和保存

### 11.1 关闭决策与完成阶段

普通内容默认直接关闭；需要时应用提供 dirty 事实与关闭决策。鼠标、快捷键、程序关闭及原生整组关闭引发的文档移除都经过同一协调入口。路由离开使用相同业务依据，但遵循 Router blocker 契约，避免一次操作重复确认。

推荐时序：确定目标及内容修订 → 请求决策 → 复核实例和修订仍有效 → 移除节点并结束实例寿命 → 结算清理与后继激活。单个 dirty boolean 不足以识别确认期间发生的新编辑，但这不要求 Worksplit 建立通用编辑版本协议。先让应用的关闭决策使用已有编辑版本与保存结果判断有效性，集成层复核实例及路由内容仍是原目标；只有内部消费证明不足时才增加公共修订能力。

本轮原生批量关闭实验证明：A 已批准但 B 的确认仍待决时，A 再次编辑，单靠 A 的 `beforeLeave` 返回时校验版本不能保护提交。最小补充为 `getCloseRevision(): string | number`，读取应用已有编辑修订；集成在批次接纳与全部决策完成时比较，不生成、递增或持久化版本。涉及多个内容实例时，dirty 成员缺少该 getter 则在决策前明确拒绝（`revision-required`）；原先 clean 成员变 dirty 也使批准失效。工具的 dirty 关闭使用同一规则，无需 Router。单标签关闭继续由应用回调校验编辑修订。

- 确认期间实例仍有效；拒绝时保留内容，不提前移除节点。
- 重复关闭同一实例复用待决操作，不重复弹窗；期间的新编辑使旧批准失效，需重新取得适用决策。
- 保存后关闭只有在应用确认对应修订已保存且仍可关闭时提交；保存失败保留实例。
- 关闭后台文档不切焦点。关闭活动文档优先选同组最近使用文档，再选其他组最近使用文档，最后进入应用声明的工作台首页。
- 确认期间用户切到其他文档时，关闭完成不得抢回焦点；后继依据提交时的有效状态决定。
- 同一实例在确认期间提交了新路由内容，旧关闭批准失效，不能关闭新内容；关闭已提交后拒绝新的实例操作，晚到导航不能复活它。
- 节点已移除后清理失败，报告已关闭及清理失败的实际影响，不能伪称拒绝或恢复原实例。React 卸载也不代表应用异步清理已完成。

首轮不增加公共批量关闭 API，但必须处理原生整组关闭。推荐先取得全部受影响实例的有效决策，再提交移除；若上游无法接入，明确禁用该入口，不能绕过 dirty。

原生 pin 和 `enableClose: false` 同样约束工作台关闭入口，不能通过 `close` 绕过。整 TabSet 关闭按上游可关闭直接子节点选取成员，保留含不可关闭成员的整个 TabGroup，并包含折叠的可关闭分组；显式 `deleteTab` 批次有任一不可关闭目标时整批拒绝。原生菜单的“关闭其他／右侧／全部”按上游可见标签枚举语义执行。相同待决请求共享决策，重叠请求明确拒绝；批准后复核成员、可关闭状态、路由内容与 lifecycle。

锁定上游整组删除的差异与最小原生 Action 适配见[行为契约](../docs/vscode-workbench-behavior.md#coordination-boundary)。成员移除由生命周期协调，空分组、空主编辑目录和布局整理仍由 FlexLayout 处理；实际验收由验收记录维护。

### 11.2 内容保留与释放

推荐首次显示时创建内容；尚未显示的恢复标签不因节点存在就提前启动 loader 或业务连接。显式后台导航或应用预加载可按其声明执行路由工作，不等同于挂载所有恢复标签。首次挂载后，切换、移动、pin、最大化与收起保留内容实例。原生内容挂载机制已核对，移动及隐藏后的保留证据见验收记录。

不能仅以 Tab ID 不变证明内容保留。原型加入输入值、滚动位置、挂载计数和订阅计数，验证跨组移动、进入 Border、隐藏与恢复不会重建内容、丢失状态或重复建立连接。

隐藏不等于暂停后台任务，内容按需消费激活/可见状态并控制成本；工作台不承诺无限打开文档的成本可忽略，也不擅自卸载隐藏内容。文档内部路由变化保留 Tab 实例，旧路由内容依 Router 生命周期退出并执行离开决策。

内部 demo 测量少量和较多文档下的首次打开、切换、loader 请求次数、内容渲染次数、存活订阅与关闭后的资源变化。记录环境、文档数量和观察方法；内存观测注明 GC 等限制，不用一次堆大小读数证明无泄漏。切换和 resize 不应无故重新加载文档或使全部内容重渲染。先按测量结果调整订阅与共享资源，不预建全局缓存或自动淘汰机制，也不在实测前宣称高效。

最终关闭释放实例持有的 Router、订阅和注册资源；共享服务仍归应用。失效实例的晚到结果不能复活内容。应用撤回动态内容时拒绝新打开，旧实例明确显示不可用并释放失效资源；草稿保留及恢复由应用决定，不强造通用插件生命周期框架。

### 11.3 命令与可选持久化

快捷键、菜单和工具栏复用命令。异步命令接纳时固定目标，不能等待后悄悄转向新活动文档。隐藏但挂载的内容不能同时响应全局保存；尊重输入框、编辑器和弹窗的事件处理，内容局部操作无需全部注册为工作台命令。

持久化可选，不默认写全局 localStorage。应用启用时提供存储接线与工作区标识，保存原生布局和恢复必需的文档描述、会话数据；当前快照格式见用法，不序列化运行时 Router 或复制派生状态。业务缓存、凭据、草稿和任意 React 状态不自动打包。

恢复先校验格式、内容可用性和停靠策略，再以地址栏确定活动目标，派生高亮重新计算。未知内容或不兼容快照明确报告，提供显式重置或转换，不静默挪动标签或丢弃记录伪装成功。首轮原型不依赖持久化；后续恢复验收覆盖深链接与快照冲突、失效实例提示及无效快照的可审查处理。

## 12. 实施顺序与验收

### 12.1 验证基线与路线门槛

实现开始时记录实际采用的 FlexLayout、TanStack Router/Store/Hotkeys 和 React 版本及对应源码/文档。v0.11 demo 是外观与交互参考，不代表安装版本或 master 文档与它相同。

原型包括两个并排真实路由文档、一个全局 Inspector 或工具、类型化常驻导航，以及可控的慢 loader、redirect、错误页和 dirty 内容。沿用当前焦点与空编辑目录回归，补真实浏览器观察，不能用静态 renderer 的 demo 代替路由集成。

| 路线门槛         | 必须证明                                                                  | 未通过时的处理                                     |
| ---------------- | ------------------------------------------------------------------------- | -------------------------------------------------- |
| 原生路由接入     | 嵌套路由独立运行，hooks、类型、context、loader、redirect、blocker 正确    | 调整实例与定义复用方式，不回退到第二套路由表       |
| 提交与历史       | 去重、晚到结果、拒绝后退、连续 popstate 不破坏已提交文档与历史            | 暂停公共 API 定型，修订协调方案                    |
| 资源保留         | 移动和隐藏保留已挂载内容，关闭释放，晚到结果不复活                        | 核对上游能力，明确无法兑现的范围                   |
| 受控操作         | UI、程序 Action、整组操作、恢复均满足关闭与停靠约束                       | 收窄或禁用无法协调的入口，复核原生槽边界           |
| 内部公开入口消费 | demo 通过公开包入口完成路由、工具与生命周期，无私有源码穿透或 Pluxel 依赖 | 修正公开面及接线，不将关键协调留给 demo 私有控制器 |

两个真实应用的接入属于后续验证：检查能否删除重复协调、是否存在应用专属假设，再按证据调整接口。它不阻塞本轮内部重构交付，也不能由两个内部示例替代。

验收记录包含版本、场景、观察结果及未通过项。上游能力描述不等于本集成已经验收；测试只证明覆盖的边界。

### 12.2 行为验收

| 场景                         | 必须观察到的结果                                           |
| ---------------------------- | ---------------------------------------------------------- |
| 简单页面                     | 常驻导航与中央内容即可工作，无空 pane 或存储前提           |
| 两个路由文档                 | params/search、loader 与内容独立，焦点决定地址             |
| Explorer 联动                | 更新归属高亮，不抢工具选择/树焦点，无导航循环              |
| 底部 Border                  | 内容收起保留标签条，无可用工具不留空条                     |
| 原生槽和普通 Tabs            | 能定制内容，无额外布局节点，键盘/拖动仍正确                |
| 移动、pin、最大化、收起      | 状态和资源保留，不重新实现原生标签系统                     |
| dirty 关闭和导航             | 拒绝后保留原实例；所有入口一致                             |
| 前进后退、异步竞争、去重冲突 | URL 与已提交文档一致，不抢回焦点或丢失内容                 |
| 受限拖放、程序 Action、恢复  | 相同策略在所有入口生效                                     |
| 内容错误                     | 仅影响该实例，不重建工作台                                 |
| 内部 demo 消费               | 通过公开入口完整运行，无 Pluxel 依赖或私有协议穿透         |
| 文档数量与资源成本           | 记录请求、渲染、订阅和关闭清理的测量结果，不因切换重复加载 |

首轮使用原生 pin 和核心键盘能力，补工作台焦点协调；不引入 preview 自动替换、复杂快捷键编辑器、通用上下文工具编排或多窗口协议。缩小窗口保留原生布局、明确的最大化选择和内容资源；应用需要单文档呈现时用原生能力主动选择，不增加库级手机布局策略，证据见验收记录。

### 12.3 分步交付

1. **路由与协调原型。** 完成两个文档、一个工具、类型化导航、dirty 和竞争场景，证明第 9、11 节关键规则并跑通基本原生移动。
2. **内容与原生扩展验证。** 覆盖 Border、pin、最大化、整组关闭、内容保留、受控 Action 和定制槽，验证简单页面无空 pane、工具不接管文档 URL。
3. **内部消费与 API 收敛。** 将 Worksplit 自有 demo 完整迁移到公开入口，确定最短完整调用、必要扩展及 exports；验证导航/Explorer 投影无焦点抢占或循环，记录资源成本。demo 消费库提供的协调，不另写一套仅供展示的控制器。
4. **内部正式替换。** 完成可选持久化、原生窗口缩放与手动最大化、错误隔离和现有行为回归，删除 Worksplit 内部被替代实现，更新用法及适用的发行说明。按现有脚本完成静态检查、测试、构建和真实浏览器验收；此阶段完成才算本轮重构交付。
5. **后续应用接入，另行执行。** Worksplit 内部交付后再迁移 Pluxel 和第二应用，删除它们的重复接线并验证通用性。本轮仅记录已知迁移影响，不修改消费应用或承诺其现有构建已兼容新 API。

原型可隔离存在，但正式路径不长期保留双引擎或新旧状态同步层。每步用证据决定是否进入下一步，不因 demo 能显示就默认整个设计成立。

## 13. 迁移归属与删除标准

| 当前职责                                       | 迁移后所有者              | 删除或保留标准                                                         |
| ---------------------------------------------- | ------------------------- | ---------------------------------------------------------------------- |
| editor arrangement、编辑拓扑、标签 DnD         | FlexLayout                | 内部 demo 迁移并通过行为回归后删除库内被替代实现；应用接线留待后续迁移 |
| 文档 open/activate/close、dirty 协调、地址同步 | Worksplit                 | Shell 和网格不再各自维护控制器与确认逻辑                               |
| pathname 到页面的重复分发                      | 应用路由定义与文档 Router | 原生路由覆盖真实页面后删除手工匹配                                     |
| 插件身份、发布、RPC、远程 renderer、业务保存   | Pluxel                    | 保留应用所有权，Worksplit 只消费必要内容与回调                         |
| 基础 SplitView、文档内部 pane                  | 实际 Pane Kit 消费者      | 按真实用途保留，不因替换工作台而整体删除                               |
| 旧布局快照                                     | 显式迁移或重置            | 必要时一次性转换，不长期保留兼容读取链                                 |

完成时检查旧符号、exports、入口、样式依赖、文档及生成项目的 AGENTS。用户用法写入当前 README/docs；本页保留明确设计状态，不成为第二套当前 API 教程。

独立分支允许移除旧工作台 API，不为尚未接入的 Pluxel 长期保留双引擎或兼容 wrapper；仍有独立用途的 SplitView 保留。修改限于 Worksplit 自身，并列出后续 Pluxel 的破坏性接入点。建议从当前 Worksplit 工作树创建隔离 worktree 与新分支，先将本设计稿及必要的未提交修改原样带入并核对；不要仅从 HEAD 创建后遗漏最新设计。此操作不切换当前子模块工作树，也不改变 Pluxel 所记录的子模块版本。

Worksplit 库、公开入口 demo、测试、文档及内部浏览器验收已实施；本轮继续复核并减少对原生选择、焦点、滚动、错误边界与尺寸更新的干预。多 Router、提交与历史、原生内容保留和受控 Action 的历史通过范围及新增证据见 [验收记录](acceptance.md)，原先性能测量不自动证明新增能力的成本。Pluxel 与第二应用接入仍未执行，不宣称已有兼容性。
