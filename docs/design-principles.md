# Worksplit 设计原则

跨模块取舍通过[场景预演](proposals/worksplit-redesign-scenarios.md)解释；本页保留长期原则，不重复实施接口。

## 产品定位

Worksplit 是以 FlexLayout 为布局基础、以 TanStack Router 为文档路由基础的 React 工作台集成库。
它提供文档实例、打开与复用、活动文档和焦点协调、受保护的离开、内容资源释放，以及可直接使用的默认工作台交互。
下游应能直接复用 FlexLayout 的模型、术语、Actions、props/ref 与样式知识，只学习 Worksplit 增加的文档协调。
11 月 4 日进一步明确：这是库的设计目标。丰富的下游功能应由少量能力组合出来，核心保持中性、清楚和高效，
并将未来升级 FlexLayout 的维护成本作为架构取舍的一部分。

设计目标同时包括正确性、下游接入成本、运行成本和可维护性。不能只按库代码行数或导出数量判断轻量。
一个把重复状态解析、焦点恢复、关闭复核和菜单接线交回每个宿主的接口，即使源码短，也没有完成集成职责。

中性体现在没有隐藏的业务假设；泛用体现在能力可以被不同宿主组合；实用体现在正常接入有完整默认体验。
默认行为应明确、可覆盖，并有实际消费者证明。不要为了假想宿主创造配置语言、插件协议或多级 controller 框架。
协调部分维护文档与上游之间必须成立的不变量；默认菜单、链接和常用放置策略使用这些能力组成可直接用的体验；宿主用普通函数和 React 组合业务。
这三种职责不要求再拆三个框架或包。库既补齐中性协调，也交付有实际需要的常用组合；不能以“能组合”为由让每个宿主重写它们。

## 适度包装的判断依据

新增或保留一个公共包装，依次回答四个问题：

1. 它表达的是稳定、常见的使用意图，还是只把一个原生方法换名？
2. 它减少了重复选择、生命周期或顺序敏感的工作吗？要给出实际调用方的前后变化，不能只减少表面参数。
3. 它是否保留原生模型、类型和操作路径，成本与失败边界是否清楚？
4. 高级使用者能否改用明确参数或普通函数实现自己的选择，仍经过同一接纳和保护入口？

“旁边打开”可以是库内置的目的地选择函数：它省去重复的方向判断，却不决定业务预览、阅读父层或窗格数量。
“显示并聚焦工具”应由一次操作完成，不能要求每个页面重新组合展开、选择、最大化与 focus。
关闭其他/右侧/容器内标签也有稳定范围语义，应让菜单和程序调用共用。
原生改名、调整尺寸则继续使用 Actions；财务 588px、两窗格时忽略方向、返回某报告属于应用普通函数。

常见路径应有明确默认和完整操作；定制只替换选择或呈现，不复制接纳、批准和清理。
内置策略与自定义策略使用相同输入输出，没有专用执行分支。一个组合函数不需要策略注册表、优先级链或插件协议。
应用自己的组合也应集中在已有 owner/helper，不能把业务判断分散到每个按钮。
不要为了覆盖所有可能变化给一个便利函数堆叠开关；出现不同语义时，允许调用方直接使用现有组合能力。

实施评审保留一段最短完整调用、一项失败例子和它替调用者承担的工作。能靠测试和有限代码说明的约束不提升为新框架。
只有真实消费者的选择不同才增加配置；只有实测重复工作影响性能才引入可正确失效的缓存。

## 所有权只有一个权威

| 状态或机制                                                          | 权威所有者                             | Worksplit 应做的事                                     |
| ------------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------ |
| 布局树、TabSet、TabGroup、Border、选择、尺寸、pin、最大化、拖放命中 | FlexLayout Model / Layout              | 保持唯一原生模型，接入原生 Actions 和呈现扩展          |
| route tree、匹配、params/search/hash、loader、文档内导航、错误页    | TanStack Router                        | 每文档独立 Router/history，复用应用路由定义与原生类型  |
| 文档实例、复用身份、预览资格、MRU、跨文档操作资格                   | Worksplit                              | 维护内容实例和上游之间的关系，阻止晚到结果复活旧实例   |
| DOM 与窗口焦点                                                      | 浏览器                                 | 观察事实，并协调显式的显示和聚焦请求                   |
| 浏览器地址与历史                                                    | 浏览器；工作台范围由唯一协调者写入     | 只发布已经接纳的文档位置，正确处理遍历、拒绝和宿主接管 |
| 未保存修改、业务阻止原因、保存回执、共享草稿、查询缓存、RPC         | 应用                                   | 提供读取与决策入口；库不推断业务已保存或远程工作已取消 |
| 菜单与键鼠的通用工作台体验                                          | Worksplit 默认组合，底层复用原生能力   | 所有入口调用相同操作和保护链；宿主可以定制呈现和条目   |
| 通用旁开、数量限制、产品选窗、比例与预览触发                        | 库提供可选通用组合；具体产品政策归应用 | 内置/自定义选择共用目的地契约，在统一接纳点验证        |
| 快照存储和恢复政策                                                  | 应用                                   | 库提供格式明确的导出与验证，保留原生布局结构           |

TabSet 是窗格，TabGroup 是标签条中的分组，Border 是边缘容器。文档与工具是内容角色，停靠位置不改变角色。
原生 tab ID、内容实例、路由复用身份、业务资源身份、应用批准 token 各有含义，不能因为值碰巧相等而混用。
文档内下探和返回改变位置而保留文档实例；路由 key 改变不自动结束草稿或内容资源。
所有布局可见内容与活动/聚焦内容分别表达，应用据此组合读取需求，库不调度业务查询。

每项状态区分三类：权威事实、可重建投影、一次操作的临时捕获。只有权威事实可以决定业务意义；
投影可以复用引用和索引，但必须有来源与失效条件；临时捕获随操作结束释放，不进入快照或公共 registry。
文档与工具共享同一种内容寿命所有者，差异只保留在角色实际需要的字段；多个 Map 不能各自决定同一内容是否存活。
复用 key 只回答“哪些文档可供选择”，不保证唯一；手动标题的所有权也不从 key 或字符串相等推断。

## 控制路径与竞争范围

每项语义只有一个最终决策点，多个入口共享它。原生 Router/history 拥有文档内导航，真实 blocker 调用应用离开决定；
程序入口负责关联结果，不先批准再给 blocker 发跳过票据。Worksplit 的打开负责选择实例和接纳新实例，不重演 Router 的流水线。
信息足够时先做便宜选择，未命中才分配和加载；保留既有文档不应为了查找它先执行一次临时 loader。

竞争范围由正在保护的事实决定。同文档导航、同预览槽、相交关闭范围和全局焦点各有自己的范围；
新焦点意图撤销旧请求抢焦点的资格，不自然意味着取消其他窗格的普通打开。独立工作可以并行，提交时只复核相关事实。
取消、等待和失效不得扩成全工作台 busy；确需会话级独占的退出、浏览器写入权与强制终止单独说明。
同步原生操作直接提交；异步等待只出现在实际路由、应用决定和资源结算处，不为接口整齐增加全局队列。

## 失败由拥有该能力的一方解释

路由错误页由 Router 呈现，内容渲染错误在该内容边界处理，保存失败由业务报告，Worksplit 报告接纳/布局/协调的结果。
一个标签的加载或渲染失败不应销毁其他标签、重建整个 Model 或停止所有业务服务。
已接纳的错误页仍是可定位、关闭和恢复的文档；不能为了把所有错误统一成一个 failed 而丢掉原生错误体验。

恢复与重试由发生失败的能力负责。库不重试业务写入，不用重建实例撤销已经发生的保存或原生删除。
诊断说明哪项操作、哪个内容及哪些效果已经发生即可；不为普通失败引入事务日志、自动补偿或通用任务平台。
上游缺陷、业务拒绝、正常取代和清理异常分别保留事实，测试也在各自真实边界证明它们。

## 原生优先，协调完整

直接采用上游类型、组件、Actions、路由参数、React provider 和浏览器 AbortSignal。
上游已经完整表达的能力不再提供一套改名后的等价体系。Worksplit 的公共能力应补足真实协调缺口或完成有实际价值的常用组合，
例如把异步离开决定接到原生关闭，把拖放结果接到文档接纳，或为旁开选择适用的原生目的地。
不逐项转写原生类型、节点、布局属性和 Actions，不把上游方法改名后再包一遍。
接入后的布局问题仍能用 FlexLayout 的术语解释和定位；必要变化只有协调入口与其保护含义。

布局和路由不建立长期镜像。确需拓扑预检时可使用短寿命原生候选，明确其保真限制，由原生 Action 执行布局与空节点整理。
查询不通过序列化整个 Model 实现，也不触发原生 save listener。序列化是明确操作。
原生保护能力必须由实际路径证明，包括 history traversal；必要适配保留唯一历史存储，不为业务阅读新增第二导航栈。

原生扩展仍然可见：宿主能接触 native props、原生节点、原生布局 ref 和原生菜单条目。
这些是可信扩展，不是安全沙箱；readonly 类型不能隔离 `Node.getModel()` 的可变引用。
协调拥有的变更必须经过 Worksplit 的公开操作或受控原生 Action 入口。

无法由公开上游能力正确支持的功能，要说明范围与原因。已有上游缺陷的适配应保持最小、独立、带复现和移除条件。
不能为追求“全部原生能力可用”承诺尚未成立的多窗口、任意批次事务或模型替换语义。
版本差异集中在相关原生接线与有证据的最小适配；普通属性扩展不应要求重写 Worksplit 的平行类型或逐字段转发。
升级时重新验证边界并移除已由上游提供的补丁，不用永久兼容分支保存两套原生语义。支持范围限制须说明内容生命周期上的原因。

## 默认体验是库的交付内容

默认右键菜单应覆盖文档、原生标签组、窗格和 Border 的适用操作，包含复制、保留预览、置顶、分屏、分组编辑和批量关闭。
鼠标与键盘入口、菜单焦点交接、失效目标处理、关闭范围与操作结果处理同属集成职责。
默认呈现复用 FlexLayout；宿主可修改原生条目或替换呈现，不必引入指定 UI 框架。

文案、主题和业务动作可定制。默认中文或英文不应写进协调内核；应用的 HeroUI/Mantine 组件和业务弹窗也不成为库的依赖。
菜单选择“向右拆分”是明确操作；“有两个窗格就忽略方向并复用另一窗格”是应用策略。

策略和机制必须在代码与接口上都能区分。库可以提供可选的通用策略；把硬编码的 4 换成一个配置数字，仍不等于完成了产品选窗的归属调整。
能力需要明确的默认值，但不得隐藏财务专属的 2×2、预览方向/比例、阅读返回层级或草稿采用政策。

## 公共 API 要让效果可见

- `get…`、只读 hook 和 selector 只查询；不隐式登记 owner、创建 Router、保存或改变布局。
- `can…` 是同步预检；执行仍须复核，预检通过不是异步许可。
- `decide…` 明确返回应用的决定；`on…` 表示通知，不暗含 veto。
- 获取内容句柄与登记唯一内容 controller 使用不同入口；资源 effect 可有多个，编辑决定的 owner 只有一个。
- 布局类型沿用原生名词。`containerId` 不能命名为 `groupId`；文档活动状态和 DOM 焦点不能合成一个含糊的 active。
- 用判别联合排除互斥组合；无法由上游类型表达的约束在边界明确校验，不用 `any` 放弃路由推导。
- 有状态操作采用共同的结果词汇，区分提交、拒绝、被取代和失败；查询仍直接返回数据。
- 拒绝发生在提交前；提交后的清理或观察者失败要报告已发生的效果，不能伪装为“什么都没做”。

公共接口不能要求调用者学习内部 epoch、所有权表、Router 临时实例或动作模拟器。
内部应按不变量分工；没有独立消费者需要的 controller、event bus 或 registry 不公开。
统一结果词汇不要求统一任务引擎；能直接完成的原生效果不增加队列、命令转发或事务包装。

## 编辑事实、许可与有效性分开

未保存修改是一项编辑事实。无未保存修改不代表可以离开：写入待确认、共享资源操作等仍可能阻止关闭。
提示、保存、放弃和业务拒绝由应用实现；库统一调用决定、复核有效性、执行关闭并释放资源。

批准必须绑定被审核或已保存的状态。批准 token 不代表数据库版本，库不生成业务版本，也不从 dirty 布尔值推导版本。
状态 A→B→A 不能使旧批准复活；内容 ID 重用、controller 更换、路由资源变化、关闭范围变化也会撤销旧批准。
保存期间的新编辑必须保留；保存成功不能自动批准用户尚未确认的新内容。

单个关闭、批量关闭、预览替换、受控导航和工作台退出共用决定语义。
所有成员先取得有效决定，再开始删除；已发生的应用保存不因另一个成员拒绝而回滚。
这是许可协调，不是跨业务服务和原生 Model 的事务。浏览器终止的能力边界另按 `beforeunload` 维护。
共享决定不合并不同提交点：原生删除可紧接最终复核，Router 继续后仍有异步加载与重定向。
编辑 owner 与库的尝试寿命一起覆盖这段间隙；通知事件不能被描述成不存在的最终 veto。

## 寿命和完成条件明确

移动、隐藏、折叠和最大化不结束内容寿命。React 依赖与组件 effect 由 React 管理；内容清理只接管实际登记的资源。
共享草稿、连接和任务属于应用，关闭一个视图只释放它持有的引用。文档 Router 的寿命由 Worksplit 管理。

拒绝关闭不停止资源。批准删除后使旧实例失效，再结束相应资源 effect；晚到获取要释放，不能附着到重用相同 ID 的新内容。
`AbortSignal` 表达资格失效和合作式取消，不能证明远端操作已经撤销。
关闭等待的清理集合、晚到清理、错误报告归属、重入和幂等都需要明确规则。

`dispose` 是宿主终止资源的动作，不调用交互确认；正常用户退出必须先经过受保护的工作台关闭。
文档接纳、路由提交、DOM 绘制、业务保存、远端回执和资源释放不能共用一个模糊的“完成”。

## 配置、恢复与包边界

创建配置属于会话，React 呈现参数属于视图，内容声明属于已 commit 的内容 owner。明确各自何时生效；
不靠修改旧 options 对象或重跑初始化来热更新，不提供没有消费者的通用 setOptions/reconfigure。
启动拥有初始化和可选浏览器连接，视图挂载只借用实例；操作不能在半启动状态下猜测哪项资源已经可用。

快照是原生布局和必要恢复信息的明确导出，不是运行 store、历史备份或草稿归档。序列化字段只有一个位置，
保留原生 JSON 与宿主自己的 config；库只拥有自己的命名空间。结构坏了明确拒绝，业务依据过期由对应页面表达。
重构可以拒绝旧布局格式，不能静默丢业务事实。恢复成功不意味着 loader、权限、冻结结果或远端对象仍然可用。

包按实际独立使用边界拆分，纯函数模块不因此必须单独发布。Workbench 与 SplitView 的消费者和依赖不同，值得分包；
仅被 SplitView 使用的算法可保持纯模块并内聚其中，不因历史上叫 core 就保留一个公共基础层。
扩展使用原生 props/Actions、普通函数和 React；升级成本集中在有证据的适配处，而非扩散为平行 schema 和通用插件平台。

## 认知成本与性能一起验收

下游应能仅凭公开类型与一份完整示例实现：普通文档、可编辑文档、工具、默认菜单、拖放、关闭保护和快照恢复。
正确接入不依赖导入源码私有路径、复制布局遍历、拼接多个中间操作或绕过 dispatcher。

优化前保留可比较的行为基线，记录 Router/订阅/内容挂载数量、序列化次数、菜单与布局更新范围、关闭清理和制品依赖。
先减少不必要的 Router、loader、重复决定和跨内容更新，再考虑缓存；把同步查询变成异步或增加预加载并不自动提高效率。
必须同时说明结果是否相同、实际工作量、环境、样本与限制；不能从代码更少或微基准更快推导生产性能。

库源码、demo、独立 tarball 消费者和真实宿主分别验证。声明文件可编译不代表原生对象唯一、运行时路由推导正确、
键鼠可用或宿主资源已释放。失败和未验证范围必须保留。

## 变更与文档纪律

每项契约保留一个权威位置，概览链接到完整规则。保留设计理由、反例、失败边界及实际源文件入口。
提案明确“待实施”；历史验收不充当新设计验收。实现完成后把现行规则收敛到所属契约，过程与旧方案通过 Git 追溯。

本次整体重构按用户授权是一次破坏性替换：不保留旧 API alias、适配 shim、双实现、旧配置分支或旧快照迁移器。
旧接口和目录只提供行为证据，不是必须保留的设计输入；已有提案也可被更清楚的选择替换，不叠加并行方案。
有价值的实现和测试可以复用，但按新的统一契约整合。外部宿主迁移到新用法；迁移说明供人工改代码，不能成为运行时兼容层。
不兼容不授权静默丢弃业务数据、草稿或损坏快照。完整目标及实施交付要求见[提案](proposals/worksplit-redesign.md)。
