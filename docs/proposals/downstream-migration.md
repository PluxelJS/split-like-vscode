# 财务宿主的迁移范围与验收

财务消费者已经迁移；当前结果与缺口由父仓库 `VALIDATION.md` 记录。本页保留财务专属的范围和验收依据，
其他仓库使用[通用迁移指南](../migration.md)，不照搬财务政策。库的安装、旧新 API 映射、默认值变化、
所有者迁移顺序及通用验收由该指南统一维护。

## 财务拥有的契约

继续维护本消费者时，先读父仓库 AGENTS.md、README.md、docs/architecture.md、
docs/features/workspace.md 和 VALIDATION.md。沿用个人分支，保留已有 workspace/catalog/lockfile 改动；
Pluxel 宿主修改遵守本地 development skill 和 dev-console HMR 批次工作流。

不重设计会计、金额、账套归属、CAS、回执或共享草稿契约。财务项目 owner 仍拥有这些业务事实，
正常离开保存库返回的最终快照；存储失败报告其实际状态，不把已经完成的关闭伪装成未执行。

- **项目与资源。** `financial-project-owner.ts` 创建会话；`financial-workspace.tsx` 绑定视图；
  `financial-document.tsx` 持续 controller；`document-scope.ts` 管资源借用，引用跟随 Router 实际接纳。
  独立于文档的项目编辑由 workspaceLeave 保护，不重复遍历文档。
- **阅读返回。** 保留同标签下探、筛选 push、口径 replace、`financialReadParent` 来源索引及无父层时的
  业务回退；不镜像原生 history。金额组成的“当前报告”在操作时选择既有报告的完整 href，交给普通
  createLink 复用，保留其查询、草稿与滚动；不能重写 open 或拼装结果。
- **放置与工具。** 2×2、588px、比例和目录/详情阅读政策属于财务。使用原生 destination，保留
  source 寿命与前后台呈现语义。问题定位使用本次 activate 的 focus 回调，不靠 rAF 重试或多步拼接。
- **草稿与写入。** 无 dirty 的待确认写入仍能拒绝离开；保存只确认捕获的那份草稿。已确认提交导航
  与普通导航分开，但同目标并发尝试也不共用批准。每个 owner 释放自己的写入令牌，同 ID 新寿命
  不接受旧回调。共享草稿不随隐藏或临时卸载销毁，未知写入先查询或恢复真实回执。
- **恢复与存储。** 使用稳定项目 workspaceId；宿主管 envelope、合并写入、错误展示和最终 writer
  封存，库验证 v2 数据。旧布局不兼容需明确重置；不能删除业务数据，也不能让延迟 writer 覆盖退出快照。

## 本消费者必须保留的验收

结合父仓库规定的聚合 verify，在实际桌面、紧凑边界及原生 2×2 中验证：

1. 目录旁开预览、保留与多副本复用；满 2×2、588px 金额列、中央/Border 移动及工具揭示。
2. 下探→中间筛选→返回来源；“当前报告”的完整条件、background 与失效 source；直接地址回退。
3. dirty、无 dirty 的 pending write、保存中新编辑、批量关闭第二成员拒绝和多个内容借用同一草稿。
4. 慢业务链接后切页，浏览器 Back 等批准期间后台打开；晚到结果不得抢回前台或混用批准。
5. 同名手动标题在导航/恢复后保留；问题定位、独立滚动、菜单退出焦点和实际拖放失败反馈。
6. 正常退出与外部交接保存最终快照；存储失败准确反馈；重复恢复及懒加载标签返回保持精确实例数。

真实 UI 只读或草稿操作不等于真实后端写入验收；受控 fixture 不证明外部 S3 或模型服务。
库源码、安装制品和财务宿主分别记录证据，不能继承旧计数。更新本项目现行契约、验证摘要与 gitlink；
提交、推送和合并按当前任务授权执行。
