# Worksplit 整体重构实施说明

状态：**2026-11-04，待实施**。本页只安排执行与证据，不重复接口规范。
目标是下游直接使用 FlexLayout/TanStack 原生能力，并获得完整文档协调和默认体验。
用户选择破坏性替换，外部应用迁移用法；目标契约见[整体提案](worksplit-redesign.md)。

## 建立一条实施路径

1. 读取 README、适用 AGENTS，核对分支、工作区、跟踪与实际依赖/补丁。沿用个人分支并保留他人改动；本页不授权主线合并或发布。
2. 阅读[设计原则](../design-principles.md)，沿[场景预演](worksplit-redesign-scenarios.md)追踪实际用户路径，再读整体提案的对应契约。
   当前[架构](../../refactor/README.md)、[行为](../vscode-workbench-behavior.md)和[资源](../resource-lifetimes.md)用于找必须保留的不变量。
3. 重新核对消费者 checkout 与安装制品。财务场景基线为 `0ce93ea4`，本轮复核到 `39721c93`；Shell/Studio 的旧调查不代表当前状态。
   实际授权范围内的外部应用需要迁移；缺环境或授权的消费者保留精确缺口，不用兼容层伪造完成。
4. 从 `packages/react/src/index.ts`、`integration.ts`、`document-history.ts`、`workbench.tsx` 追踪真实控制路径。
   原生能力以锁定源码/公开类型为准。记录实际安装与 lock 的差异，不让本机恰好可用替代制品要求。
   先核对[原生组合与升级边界](worksplit-redesign.md#原生扩展与写入边界)：沿用上游类型/Actions/props/ref，列清必要适配及移除条件，不先搭通用包装层。
5. 依据[包装判断](../design-principles.md#适度包装的判断依据)检查最短完整调用：常用意图由库完成，产品组合集中在应用 owner。
   每个包装写明省掉的重复工作、可定制处及失败边界；按[统一取舍](worksplit-redesign.md#常用组合的取舍)落实，不另造公共方法族。
6. 按[全方向复查](worksplit-redesign-scenarios.md#全方向架构复查)核对状态/控制/竞争/失败/启动/恢复/发行。
   旧 API、包名、Map 和旧政策测试均可替换；不能只删兼容别名，却保留同样的重复所有权与批准路径。

## 先验证会推翻架构的边界

先证明导航接线及必需修正可由独立消费者取得，再用完整小例子检验公开接入；两者成立后展开模块与消费者迁移。
以下[代表路径](worksplit-redesign-scenarios.md#实施时先证明什么)贯穿这一顺序，不要求先实现完整菜单、包拆分或宿主改造才能证明导航边界：

- 选定的唯一文档 history 与真实 Router 配合，验证五类导航、全部 blocker 之后的提交资格和实际索引；复现 T1 等其他 blocker、T2 完成后 T1 晚返回。
- 验证同地址重载/invalidate/错误重试的无批准 redirect，以及已批准链的继续：既能阻止改写，又能结算原生调用，不靠私有 Promise 或 URL 猜归属。
- 离开批准到 Router 最终接纳之间的临时编辑保护与 defer 结算，明确尚未提交和已提交 history 两种竞争，覆盖后台 Router、隐藏 owner、失败与取消。
- 内置旁开与产品 resolver 共用接纳，接通下探与浏览器/页面混合返回；原 entry 保留 state，失效引用按 URL 新接纳，不复制返回栈。
- 多窗格可见性、具体焦点请求、默认/定制菜单及范围关闭，测量有界原生预检的真实工作量。
- 正常及外部退出在终止前捕获最后快照，覆盖节流未 flush、导出重入/失败、存储失败和旧 writer 晚写；强制终止不被导出阻塞。

首先产出一份真实依赖下可执行的最小接线：明确每次 history 请求、原生加载/redirect、已接纳 entry 与尝试终态如何关联。
分别展示成功、拒绝、被新请求取代、没有进入 pending 以及无 RouterProvider 时的结算证据。不能只让 Worksplit 的 Promise 返回，而留下原生 navigate 悬空。
当前 createHistory 的公开 backend 接口尚未证明足以覆盖这些条件。若缺少最终提交或转换结算的公开能力，先选定可分发的最小上游修正，
补上支持版本、制品验证和移除条件，再开始大规模模块迁移；不把能力缺口藏进实现阶段，也不保留运行时双路径。
必需修正的最小证明同时在仓库和独立安装中运行：记录版本、安装条件、类型与运行能力，以及原生对象是否仍为唯一实例。
现有消费脚本只复制原生包版本号，不能证明工作区补丁已进入制品；依据[包边界](worksplit-redesign.md#包边界)明确交付并执行同一缺陷回归。
这个检查验证实际安装能力，无须发布 npm 或推送分支，也不提前完成所有 UI 验收。

把静态命中 preserve、活 Router 的 navigate、未命中候选和 redirect 晚命中分别跑通，记录真实 Router/loader/决定次数。
同时证明一个 content owner、一次 start、局部竞争以及合法路由错误页保留；这些影响整个架构，应先于大规模菜单或模块迁移。

沿目标公开导出建立最小只读、可保存编辑器、工具/自定义菜单三个可运行例子，再固定精确签名。
它们是后续 README/demo/独立消费夹具的起点，持续补齐同一份例子，不建立实施完就废弃的第二套示范框架。
编辑例子完整实现重叠请求的暂停引用、实际保存依据与 defer，不能把关键协议藏在占位函数中；
工具/菜单例子证明只改呈现不复制批准，链接工厂集中一次结果反馈，历史与退出分别保留原 entry 和最后快照。
只读接入无需 controller/token，编辑接线集中在一个内容根或宿主 owner；若每个页面都需手写批准循环、重建布局查询或管理内部代次，应先收敛接口。
使用这些例子检验调用方负担，而不按接口数、文件数或库内行数判断简洁；不为尚无真实消费者的变化添加公共配置。

这几条走相同的目标架构，不提供临时兼容模式。若公开上游能力不成立，记录最小反例、影响和替代，
修订同一目标契约后继续；不能先铺开模块，再靠影子历史、第二布局树或通用任务引擎补洞。

## 按依赖推进

| 阶段                | 要形成的可检查结果                                                           | 权威要求                                                                                                                                                       |
| ------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 实例、决定与历史    | 真实请求/转换关联、最终 history 提交与原生拒绝结算；再固定公开类型和最小接入 | [导航批准](worksplit-redesign.md#导航批准与转换寿命)、[history 提交](worksplit-redesign.md#文档-history-提交边界)                                              |
| 接纳、原生与查询    | open/复用/预览/明确目的地；有限预检、可见性及工具揭示                        | [打开](worksplit-redesign.md#文档打开与路由身份)、[原生边界](worksplit-redesign.md#原生动作布局限制与接纳)                                                     |
| React、交互与浏览器 | 默认菜单、controller/effect 寿命、焦点、entry 对应和带最后快照的外部接管     | [菜单](worksplit-redesign.md#默认菜单与键盘入口)、[历史](worksplit-redesign.md#浏览器历史与工作台退出)、[退出快照](worksplit-redesign.md#受保护退出的最后快照) |
| 消费者与制品        | demo、独立安装、已授权下游只用新接口；依赖/CSS 与文档一致                    | [迁移](worksplit-redesign.md#下游迁移)、[包边界](worksplit-redesign.md#包边界)                                                                                 |

分工围绕不变量，不把 integration.ts 换成一串无明确所有者的 controller。
一个操作的捕获、决定、复核与提交仍应能沿一条路径阅读；小型同步操作直接完成效果。
复用有价值的算法和保护测试，移除旧 API/旧配置/重复菜单；不为“重写”删掉已有正确性。
删除 approved[href]、多份内容寿命表、全局普通打开取代、重复 key 冲突处理及泛名 core 包；算法和必要索引保留在明确 owner 内。
下游同步移除标题字符串猜测、绕过 native name 的文本呈现及重复快照结构校验；存储、产品政策和业务依据仍保留。
运行 Pluxel 宿主的代码修改遵循其本地 skill 与 dev-console HMR batch 流程；纯文档修改不操作运行实例。

## 验证与完成

每段行为先做受影响检查；稳定后按仓库根 verify 和[完整验收矩阵](worksplit-redesign.md#行为验收矩阵)交付。
测试与任务串行并保留缓存；纯文档修改检查格式、链接、阅读路径和源码一致性，不重复执行运行验收。

分别记录源码类型/单元、真实 Router/Model、独立 tarball、浏览器键鼠与实际宿主证据。
确认宿主加载的确是新版本；性能比较保持相同行为、样本与环境，并记录候选构造、序列化、Router/订阅/挂载数量。
将前述三个接入例子纳入公开 README 与制品验收，确认实际调用仍与已固定的签名和保护语义一致。
历史示例同时操作浏览器返回与页面返回，不能只检查 URL；退出示例从尚未 flush 的 writer 开始，分别观察导出、终止和存储结果。
其中直接消费 FlexLayout 的实例须保留原生类型、Actions、ref、主题和菜单定制；核对新增功能与未来上游变化是否迫使下游学习重复模型。

最终按[提案交付门槛](worksplit-redesign.md#实施收敛与交付门槛)检查。
将已实施契约收敛到现行文档，预演中仍有价值的反例归入所属主题，执行过程回到 Git。
交付说明报告实际行为、迁移范围、证据与限制；未完成外部迁移和上游能力验证不能写成已上线。
