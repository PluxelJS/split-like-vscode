# Worksplit 重构场景预演

状态：**2026-11-04，设计预演，未实施**。下游要求用真实功能推演核心重构；本版继续核对导航许可、混合返回和退出快照的交界。
本文解释需求如何组合、责任为何这样分，以及哪些上游能力必须先证明。目标 API、精确行为和验收编号由[整体提案](worksplit-redesign.md)维护；不在这里复制第二套接口规范。

## 证据与阅读边界

| 对象         | 本轮依据                                                                                   | 能说明什么                                                      |
| ------------ | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| Worksplit    | `bdd1ca9`；运行代码仍为 `265bbed1`                                                         | 既有公开接口、实现和测试；重构尚未交付                          |
| 财务工作台   | 场景基线 `0ce93ea4`；本轮复核 `financial-workbook` 的 `39721c93`                           | 用户路径、业务 owner、现行快照 writer 与退出次序                |
| 上游 history | 安装及子模块 lock 均为 `@tanstack/history 1.162.5`                                         | 遍历保护缺口，以及异步 blocker 晚提交/提前分配索引的实际反例    |
| Router       | 实际安装 react-router `1.170.46` / core `1.171.39`；子模块 lock 为 `1.170.42` / `1.171.35` | 本轮时序核对针对实际安装源码；实施须对齐并验证最终声明/安装版本 |

财务路径以下均相对该仓库根；这些是有提交基线的证据入口，不是库需导入的文件或机器路径。
现有测试只提供保留行为的起点，本次没有重跑财务宿主、浏览器或全量测试。静态推演也不证明新接口已可执行。

最小 history 探针使用实际安装包，设置可启用 blocker 的 document 环境，初始 entries 为 `/a`、`/b`，注册永远拒绝的 blocker。
执行 `go(-1)` 后位置变成 `/a`，blocker 调用 0 次；再 `push('/c')`，位置仍为 `/a`，blocker 调用 1 次。
这定位的是上游 memory traversal 能力，不据此推断所有业务路径都已发生数据丢失。
源码入口为上游 `createHistory.tryNavigation` / `createMemoryHistory` 与本库 [document-history](../../packages/react/src/document-history.ts)。

本轮又用实际安装 Router/core、Node v24.16.0 和隔离 JSDOM 做了三项探针；启用 `node --conditions=browser`，确保加载客户端分支，
没有挂载财务应用、连接宿主、RPC、数据库或现有浏览器。财务仓库忽略目录 `.artifacts/worksplit-review/` 保存 probe.mjs 和 results.json；
普通 Node 服务端条件下的早期探针不能证明客户端行为，不计作通过证据。

| 实际操作                                                                       | 观察结果                                               | 对设计的影响                                           |
| ------------------------------------------------------------------------------ | ------------------------------------------------------ | ------------------------------------------------------ |
| 初始 /a，登记永远拒绝的 blocker；再次 navigate /a，beforeLoad 改为 redirect /b | 最终 /b；blocker 调用 0 次                             | 同地址重载也可能离开资源，不能假设 redirect 都有原批准 |
| 相同准备后 router.invalidate({ sync:true })                                    | 最终 /b；blocker 调用 0 次                             | 读取刷新与资源离开需要在真正转换处区分                 |
| T1→/b 的第一个 blocker 允许，第二个等待；T2→/c 完成，再允许 T1                 | 接纳从 /c 回到 /b；两次 PUSH 后 length=3，index 仍为 1 | 原生历史不保证旧等待失效，提交后通知与索引也须统一处理 |

前两项源码对应 Router.commitLocation 的同地址 load 及 followRedirect 的 ignoreBlocker；第三项对应 history.tryNavigation 的 await 链和询问前分配索引。
这证明旧依赖路径的风险，不证明新 history 适配、运行中的业务数据丢失或全部 Router 版本具有相同行为。
尤其不能从“可以提供 createHistory backend”推导“已能识别每条 redirect 归属并结算被拒绝的 Router Promise”。

阅读顺序：先沿下面的旅程理解边界，再去主提案核对接口，最后按[实施说明](worksplit-redesign-implementation.md)验证最可能推翻路线的能力。

## 全方向架构复查

本轮按无旧 API 兼容负担重新检查整个设计。覆盖如下，不能把“有原则”或静态审查等同已经通过运行验收。
原则由[设计原则](../design-principles.md)拥有，下面记录各方向的反例和选择，精确契约仍在主提案。

| 方向               | 实际证据或会暴露错误设计的反例                                                              | 本轮裁决与验证边界                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 实例与状态所有权   | integration 的 documents/tools/toolOwners/contents 分散持有寿命；同 ID 重开不能继承旧 owner | 一个判别 content record，索引只引用它；统一释放仍需真实关闭回归                                     |
| 控制路径与成本     | open 已有静态复用快路径，navigateSession 却另有 decide + approved[href]                     | 先选择实例、未命中才加载；活 Router 的真实 blocker 独占导航决定，早晚命中成本分别实测               |
| 身份与业务         | 两份不同条件报告后来筛到同一 URL，仍可独立阅读/编辑                                         | key 只是复用候选，重复正常；删除冲突 issue 与 multi 特判                                            |
| 并发与取消         | 无关普通打开被全局 epoch 取消；另一 blocker 等待时旧导航还能晚提交                          | 独立接纳与前台发布分开；同文档在全部 blocker 后复核提交资格，不能只信任原生取代                     |
| 失败域             | 一个 loader 进入原生 error/not-found 页，其他标签仍可正常工作                               | 内容错误保留为文档；协调失败与业务回执分开，不重建整个会话来补偿                                    |
| 生命周期与配置     | 当前宿主配对 connect/start，视图却能先加载；无运行中重连消费者                              | start 一次拥有初始化/可选浏览器，配置分会话/视图/内容；半启动不接收变更，先证 StrictMode/启动期遍历 |
| 标题与可访问性     | financial-workspace 用字符串猜自动名，rich label 又绕过 native name                         | 原生 name 唯一最终值，手动所有权显式保持；自动候选进内容 owner，呈现槽只装饰                        |
| 恢复与持久化       | 快照校验重复；旧 resultId 失效；150ms writer 尚未 flush 即退出                              | 单份结构校验；业务失效由页面表达；持续失效订阅与终止前最后导出分工                                  |
| 查询与性能         | 逐文档快照查询、重复 loader/Router 和广泛更新增加真实工作                                   | 保留只读投影/事件失效，优先删除多余工作；性能结论待等价路径测量                                     |
| 原生扩展与升级     | ref/props/Actions 有实际消费者；已有补丁有局部缺陷证据                                      | 保留原生形态和可信边界，适配带移除条件；不承诺多窗口或任意事务                                      |
| 默认交互与业务组合 | 通用范围、焦点、拖放接线重复；阅读父层与报告选择仍各有产品含义                              | 保留上一轮常用组合，业务在已有 owner 集中；键鼠/窄窗格/默认及定制呈现仍待实测                       |
| 模块与发行         | core 的真实运行时消费仅 SplitView，其他引用为构建/夹具/声明                                 | 算法内聚 split-view 纯模块，只发布两个用途明确的包；独立制品验证保留                                |

这些裁决会删除旧 Map 所有权、重复批准、全局普通打开取代、冲突提示、标题猜测、重复恢复校验、分离启动接线和泛名包。
它们保留既有用户需要的能力，改变的是维护这些能力的路径；旧政策测试不自动成为新设计的约束。

## 先分清需要保留的状态

| 状态                              | 所有者与寿命                        | 一个会暴露混用的例子                                              |
| --------------------------------- | ----------------------------------- | ----------------------------------------------------------------- |
| content handle / 原生 tab 实例    | Worksplit；实际关闭结束             | 同标签 A→B→A 仍是同一文档；关闭后同 ID 重开则是新实例             |
| 当前位置、entry state、history    | 该文档 Router / 唯一 memory backend | 下探和返回改变位置，不销毁整个文档                                |
| 当前复用 key                      | Worksplit 从已接纳路由解析          | 同资源筛选可以改变 key；不能因此清草稿或重建 Router               |
| 业务资源、草稿和修改代次          | 应用业务 owner                      | 两份报告视图可共用一份草稿；同文档改指另一分录则要更换资源引用    |
| 冻结金额依据、读取缓存、滚动/选择 | 应用各自已有 owner                  | 旧报表组成不能因缓存失效而换成新数字；返回 URL 不保证恢复内存结果 |
| 布局、选择与布局可见性            | 原生 Model / Layout                 | 四个窗格可以同时可见，只有一个获得键盘焦点                        |

这里不引入统一“工作资源”对象。各状态已经有生产者和寿命；库只补足它们相交处的协调。

```mermaid
flowchart LR
    Intent[应用：点击 / 下探 / 返回意图] --> Open[跨文档 open / activate]
    Intent --> Navigate[本页 Router navigate / history.go]
    Open --> Admission[Worksplit：复用 / 接纳 / 放置 / 焦点]
    Navigate --> History[唯一文档 history 与离开保护]
    History --> Router[原生 Router：加载 / 重定向 / 接纳]
    Admission --> Layout[唯一 FlexLayout Model]
    Router --> Resource[应用：提交后更换资源引用]
    Layout --> View[只读位置与可见性投影]
```

## 用 FlexLayout 知识完成组合

库的接入应允许熟悉 FlexLayout 的开发者直接表达已有意图，只为内容协调增加必要入口。
以下是目标接入的阅读方式，不要求建立新的布局 facade：

| 外部想做的事                         | 继续使用的知识                                         | Worksplit 增加的内容                                  |
| ------------------------------------ | ------------------------------------------------------ | ----------------------------------------------------- |
| 将标签移到右侧、分组、改名或调整属性 | 原生 Actions、DockLocation、节点 ID                    | 动作经 dispatch 维护内容/政策边界，原生算法与参数不变 |
| 自定义标签、工具栏、图标或主题       | ILayoutProps 呈现槽、真实 ILayoutApi ref、原生 CSS     | 仅保留库拥有的 model/factory/onAction 等入口          |
| 定制右键菜单                         | 原生 PopupMenuEntry / ContextMenuBuilder 与 React 呈现 | 默认组合补足文档语义、关闭保护和焦点交接              |
| 从业务目录旁开内容                   | 原生路由目标、明确原生落点                             | open/createLink 处理文档复用、接纳与呈现              |
| 当前标签下探和返回                   | Router navigate、history 和应用 entry state            | 文档实例保持与必要的离开保护                          |

例如移动现有标签仍可直接表达为原生动作：

```tsx
import { Actions, DockLocation } from "flexlayout-react";

const result = await workbench.dispatch(
  Actions.moveNode(tabId, targetTabSetId, DockLocation.RIGHT, -1),
);
```

调用者处理操作结果；移动仍是移动，复制文档另用 duplicate。无需再学习 Worksplit 自己的 split/move/resize 语言。
复用知识也不意味着绕过内容保护：原生节点可查询，协调拥有的变更通过上述入口；本次不支持的多窗口/模型替换仍有明确边界。
默认菜单与链接用同一组能力组成，宿主可以只改变业务选择，不复制整套关闭、焦点或布局解释。

**裁决：**用原生消费例子检验组合是否实用；核心不因下游多一个业务动作就新增一个同名 API。
类型、属性与动作保持上游形态，版本差异按[升级边界](worksplit-redesign.md#上游升级边界)集中处理，不层层转写。

## 常用组合应该做到哪一步

“调用方能够组合”还不够，还要看正常操作究竟让调用方承担了多少工作。
本轮按[四项标准](../design-principles.md#适度包装的判断依据)复查：有稳定意图、减少实际重复、保留原生模型，并可通过同一底层能力定制。
此前把自动选窗一概归应用的表述过严；普通旁开也需要写父链方向查找，并没有帮助下游复用 FlexLayout 知识。

同时，财务已经有自然的组合位置：`financial-project-owner.ts` 集中 pageLink/entryLink、当前报告选择和产品选窗，
`financial-document.tsx` / `reading-link.ts` 集中下探返回。这些普通函数继续存在，页面只传业务目标，
不需要每个按钮学习 destination、父层 state、反馈接线和全部保护规则。

另几个可以检验包装价值的真实反例：

- `workspace-menus.tsx` 递归叶子、过滤和拼关闭动作；只交付默认菜单、却不让自定义工具条使用相同范围关闭，会再次复制同一段逻辑。
  因此扩充既有 close 的有限目标形态，呈现仍使用原生条目；无需关闭命令 registry。
- `pageLink/entryLink` 已有集中结果反馈；拖放发生后没有页面代码可以直接 await。createLink 需要保留一次反馈入口，
  普通页面仍只消费链接，不新增事件总线。
- `problems-panel.tsx` 激活后用 rAF 再定位问题，反映焦点请求已经被拆散。复用 activate 内已有的实例/代次调度，
  支持本次具体 focus 回调，业务仍检查问题与 DOM ref；不引入诊断平台或对 DOM 的轮询。
- 每个编辑器都手写尝试结束、晚注册和解除暂停，会重复容易出错的寿命接线。复用 defer 的登记习惯即可，
  库不需要理解业务编辑、保存回执或草稿版本。

**裁决：**库提供少量完整常用操作，应用在已有 owner 中集中业务组合。每处便利都能说明它删除了什么重复工作，
不因为其他方法有 can/get/execute 就补齐对称方法族。具体边界见[常用组合的取舍](worksplit-redesign.md#常用组合的取舍)。

## 首层旁开与明确放置

用户从左侧目录点凭证时，右侧显示可替换预览，左侧焦点、地址与滚动保持；报表金额组成则在右侧打开普通文档并激活。
旁开位置、预览资格和呈现意图分别决定，不能从“在右侧”推出 preview/reveal。目录首层旁开后，后续阅读不应不断增殖窗格。
财务 `financial-project-owner.ts` 的 `previewPageLink/entryLink` 与 `report-workspace.tsx` 的金额打开入口是现有生产路径。

应用在点击时取得来源 handle 和目标业务地址，决定 preview、presentation、首选方向与新窗格比例。
Worksplit 解析路由、优先复用；只有确需新实例时才调用一次同步 destination resolver。
resolver 从当前原生容器/预览/MRU 投影和 `canPlace` 选择目的地；库复核实际来源、落点、焦点与政策后，通过原生 ADD 接纳。
多个候选共用这次路由解析，不能尝试右侧失败后又重跑一次业务 loader。

普通宿主直接用内置 beside，选择同方向适用的原生窗格，否则新分屏；需要产品选择的宿主传自己的函数。
两者只替换 destination，复用、预览、来源保护和接纳仍是一条路径。首次空工作台可沿普通 open 默认接纳，
避免固定旁开入口先做一次空态判断；已有来源后来失效则拒绝，不能伪装成首次打开来随意找一个窗格。
这个区别同时保持常用入口简洁和异步来源可靠。方向按原生分割结构定义，不声称按屏幕像素寻找最近窗格。

当前财务规则是：最多 2×2；凭证优先右侧，首次两侧各半；报表组成优先给右侧 588px，比例限制 25%—65%。
已有窗格与用户手调比例不重置。这些数值和选窗次序留在应用普通函数，库交付无四窗格上限的默认机制。
“下方、35%”是旧表述，不构成本次迁移要求。

如果等待时来源关闭/移动、目标被替换或焦点保护无法成立，旧打开不提交到错误位置。
对预览路径，新预览成功后才处理旧预览；旧内容有修改或拒绝非交互离开时成为普通文档。
复用既有文档保留其位置；要独立比较时明确 new，而非先接纳再暗中移动。

**裁决：**保留 placement 的有用意图。库提供中性的默认旁开组合，应用集中不同的产品选窗；两者共用接纳。
无需“财务预览模式”、策略注册表、自动方位 DSL 或第二份布局树。对应[放置与呈现](worksplit-redesign.md#打开选项)、A07–A12、A16。

## 同标签下探筛选与返回

具体旅程：试算 A → 科目组成 B → 凭证查询 C → 凭证详情 D，再逐层返回。
`financial-document.tsx` 的 `drillTo/readLink/goBack`、`reading-link.ts` 及 `journal-workspace-browser.test.mjs` 是证据入口。

普通阅读先按完整目标 href 查现有文档：已存在则保留式复用它；不存在才在当前文档 Router 中继续。
这个先查后选择的产品政策归应用。原生 navigate 在其他路径产生相同复用 key 时，两份实例正常保留，
不再发冲突提示，不为了全入口唯一接管 Router，也不在接纳后擅自关闭另一份草稿。

同标签路径保留 content、Router 和文档级订阅，仅改变已接纳路由及应用资源投影。
应用将“发起这次下探的位置”写入新 entry 的 history.state；财务字段名为 `financialReadParent`。
它只是来源指针，不是另存的 URL 列表或 Worksplit 阅读栈。

| 操作                      | 当前 entry          | 应用来源标记                | 用户返回结果                   |
| ------------------------- | ------------------- | --------------------------- | ------------------------------ |
| 从 A 下探 B               | A 在 4；B push 到 5 | B.parent = 4                | B 可返回 A                     |
| 在 B 筛选两次             | B 到 6、7           | 保留 parent = 4             | 一次阅读返回跳过本层筛选，回 4 |
| 从筛选后的 B 下探 C       | C push 到 8         | C.parent = 7                | C 返回 7，恢复筛选后的 B       |
| 在 C 切换同单元格金额口径 | replace 当前 8      | 保留 parent = 7             | 不增加一层阅读                 |
| 从 C 返回，再从 B 返回    | go 到 7，再 go 到 4 | 使用目标 entry 自己的 state | 逐层恢复来源条件               |

表中 A/B/C 是通用阅读层，金额口径一行对应报表组成路径，不要求凭证查询具备金额切换。
索引只属于同一个文档 history。筛选保留应用 state 与 hash，不覆盖原生 key/index。
快照、新开、复制仅恢复 URL，没有这条会话阅读链；直接打开时由页面给出明确的“返回目录”等目的地。
现有试算明细会 replace 到同条件主表并清除明细 account/basis；其他页面不能伪造“上一页”。
滚动/选中行由既有表格和页面恢复策略负责，history 能恢复地址不等于能恢复所有 UI 状态。

Ctrl/Meta 等显式另开、指定方向和原生拖放保持独立意图。应用可以用一个普通 ReadingLink 组合对象复用目标，
不需要给库增加 read/inspect/drill/return/edit 命令语言。原生 drop 的 target、location、index 优先于点击的自动放置。

**裁决：**下探和阅读父层由应用组合原生 Router；核心必须补齐 history traversal 的离开保护。
当前 memory go 不经 blocker，不能直接沿用“原生一定保护返回”的假设。目标由[文档 history 提交边界](worksplit-redesign.md#文档-history-提交边界)约束，
保留原生 history API 和唯一存储，先证明完整批准/提交/结算，再接通这条真实阅读链。对应 A14、L17、H07。

## 浏览器返回与页面返回交叉

同一文档内从 A 下探到 B，再到 C；B 的 entry 保存 parent=A。用户按浏览器 Back 到 B，随后点击页面的“返回来源”。
如果 browser coordinator 只按 B 的 href 再 navigate/replace 当前文档，就可能丢掉 B 自己的 state；地址虽对，第二次返回已经没有真实依据。
现有 browser-history 只记录文档 ID 和浏览器索引，不能拿它作为已保留文档 entry 的证据。

目标按实际内容寿命和原 entry key 恢复，B 的 parent 仍在同一个 memory history 中；文档条目与浏览器条目只做引用关联。
两次访问同 href 但 state 不同，也不能按 URL 合并。页面直接返回属于新的前台访问，浏览器 Back 可以撤销这次访问；
浏览器触发的文档遍历只接纳当前 browser entry，不再生成第三次访问。

若原 entry 已被替换或分支截断，或文档关闭后同 ID 重开，旧引用不再成立。按 URL 新建文档并使用页面的无父层入口，
保留现存文档的阅读状态；不能把旧 index 对应的新 entry 当作原来源。新接纳成功后重绑当前 browser entry，避免每次访问都新建。
这不改变布局快照只恢复 URL 的边界，也不要求复制应用 state 到浏览器。

**裁决：**浏览器负责前台访问，文档 history 负责本实例阅读；[主提案](worksplit-redesign.md#浏览器条目与文档-entry)定义唯一映射与回退规则。对应 H09–H10。

## 返回当前报告与多视图身份

金额详情的“当前报告”按 reportProfileId 找已经打开的报告，保留其完整条件、草稿、滚动与尺寸；找不到才按来源参数新开。
证据入口是 `financial-project-owner.ts` 的 `currentReportLink` 与 `report-tab-presentation-browser.test.mjs`。
同一个报告可以有不同期间和筛选的多个标签，不能为一个入口的便利把所有报告的默认 key 缩成 reportProfileId。

应用通过公开文档目录取得已提交位置，按自身路由类型选择目标。选定具体实例后核对 handle 并调用 activate；
仅当允许复用任意同 key 实例时才 preserve 打开完整地址，避免第二次 key 选择换到同地址的另一副本。
多个业务匹配项如何选是该入口政策，库只对同一个复用 key 使用明确的默认匹配次序。
`documentKey` 可用于已有的身份定制，但不承担业务目录、草稿分配或阅读父层。

**裁决：**保留普通文档全查询身份与业务特定入口选择两种不同判断。无需 core.openReport、全局业务资源 registry，
也不为“回当前报告”强制先 navigate 覆盖现有条件。对应[身份契约](worksplit-redesign.md#身份与原生导航)、A05、A15。

普通 open 的 preserve 命中也应直接保留会话，无需先创建临时 Router 执行业务 loader；navigate 命中才在选定 Router 中导航。
未命中候选的 redirect/并发晚命中仍按[打开路径](worksplit-redesign.md#打开先选择实例再加载)处理，不把查找与加载的成本混为一谈。

## 标题和恢复不跟随复用键猜测

`financial-workspace.tsx` 的 automaticTitles、默认名列表和字符串比较，证明宿主当前缺少明确的命名所有权。
用户把标题恰好改成某个自动名，不能因此失去手动命名；切换筛选改变全 search key，也不能暗中改回路由标题。
核心只需要一个手动所有权标记，最终值仍是 native name。业务生成自动候选，库决定是否采用；不再创建另一个 titleKey。
金额组成、凭证、企业的 rich label 同样要使用最终 native name，否则可见文字、溢出菜单与可访问名称仍会不同。

恢复也应减少重复 owner：`workspace-snapshot.ts` 不再重写库的节点/元数据校验，只保留存储和财务政策。
原生 config 的应用字段保留，Worksplit 元数据只在明确导入/导出时映射；运行中不把快照当实时状态。
writer 通过持久化失效通知决定何时导出，业务旧结果不可用与布局损坏分别处理。

**裁决：**标题所有权、复用选择和业务资源有效性各自清楚；只存无法从别处可靠推导的事实。
对应[标题](worksplit-redesign.md#标题所有权)、[恢复](worksplit-redesign.md#明确导出严格恢复)及相关目标验收。

## 编辑保存与路由提交

文档内筛选可能改变复用 key，却仍编辑同一业务资源；另一次下探可能真正离开当前分录。
`document-scope.ts` 的 `resourceKey/notifyDocumentRoute/captureDocumentScopeOwner` 区分这两种变化，
并以一次连续停留的对象身份阻止 A→B→A 后旧回调重新有效。
Worksplit 不读取财务资源类型或 CAS，只读取应用 LeaveState 和决定。

| 时间               | 事实与决定                                                               | 必须保留的结果                                            |
| ------------------ | ------------------------------------------------------------------------ | --------------------------------------------------------- |
| 请求保存并离开     | 应用捕获资源 A 和编辑修订 e7；允许继续编辑的保存阶段由应用自己的协议管理 | token 不能被当成保存快照                                  |
| 保存进入 pending   | pending 改变 leave token                                                 | 正常 token 变化不意味着保存失败                           |
| 回执已知成功       | 应用确认保存的是 e7；冻结 A 的后续编辑入口，并检查没有 e8 或待确认操作   | 若有未覆盖编辑，deny；不能批准“当前最新 token”            |
| 返回 allow(t)      | t 对应实际已处理且被保护的状态；用 request.defer 登记本次冻结释放        | 库最终复核 t 与实例资格；若在进入 Router 前失败也释放冻结 |
| 原生导航继续       | history 已获准，Router 仍可能加载、重定向或失败                          | A 的编辑入口继续受保护，草稿引用尚不因 allow 自动释放     |
| 最终接纳或确定终止 | Router 提供事实，库结束本次 attempt                                      | 应用按已提交资源更新引用；若留在 A 则恢复可编辑性         |

这个示例允许应用在保存等待期间出现 e8，从而验证拒绝；普通最小编辑器也可在决定开始就冻结全部编辑。
两者都必须在 allow 前建立保护，并证明没有把未保存编辑带入批准。冻结是应用现有编辑命令入口的可用性，
不是 Worksplit 新增的业务锁系统。外部共享编辑仍须留在独立草稿 owner，由 workspaceLeave 保护。

尝试结束会执行 defer 并结束 `LeaveRequest.signal`；signal 不编码成功或失败，不是保存回执，也不命令丢弃或证明远端请求已取消。
释放绑定原资源实例，不能解锁已改指的新编辑器。未知写入仍可在 hasUnsavedChanges=false 时拒绝离开。
defer 让宿主不必为每次决定重复处理事件绑定、晚登记和释放异常；业务的 pauseEdits 返回自己那份暂停的释放函数。
若 T1 已提交 history 但仍在加载，后来的 T2 被其他 blocker 拒绝，结束 T2 不能解开 T1 的暂停；已接纳资源仍是 A，
不能因 history 已走到 B 就把 B 当当前编辑器。这个场景比只测试一个确认框更能揭示真实 owner 与结算边界。
业务复制已提交后打开失败，只能报告视图未打开；不能把业务复制说成没有发生，也不自动重做写入。

原生删除与 Router 导航的提交点不同。删除可以最终复核后立即执行；Router blocker 放行后仍有异步工作。
本轮检查的 Router 事件没有最终提交 veto，redirect 使用 ignoreBlocker。因此不能靠 onLoad 中的第二次比较撤回已发生导航。
同资源快速允许必须基于不会跨资源重定向的路线；其他路线按离开资源保护。已批准的原生链可以延续许可，
但同地址重载、invalidate 和错误重试可能在没有决定的情况下 redirect，必须在真正改变位置前取得批准。
错误重试留在本资源无需弹离开确认；它一旦改指其他资源，就不能把“是在重试”当作跳过批准的理由。

另一个反例发生得更早：T1 已得到 Worksplit allow，仍在等其他 blocker；T2 已完成，T1 晚允许却重新 push。
这个阶段尚未提交 history，应直接使旧资格失效；不能和“history 已提交、旧 loader 仍可能接纳”混为一种 pending。
所需关联是本请求、真实 entry 和原生转换事实，不能只看 navigate Promise 完成或一次全局 onResolved。

**裁决：**共用许可协议，分别承担原生提交时序。没有新的 SaveReceipt、事务平台、业务版本或第二 Router 引擎。
实施首先验证“allow 后 loader 未完成时再次编辑、重定向、失败和被新导航取代”，不能只测对话框期间变化。
对应[导航批准与转换寿命](worksplit-redesign.md#导航批准与转换寿命)、[history 提交](worksplit-redesign.md#文档-history-提交边界)、L03–L07、L18–L21。

## 退出时保留最后布局

财务 workspace-snapshot 的 writer 按 revision 节流 150ms；financial-project-owner.stop 和当前外部历史接管都在终止前 flush。
用户拖动分屏后立即离开，或保存确认期间又改变布局，都可能使已落盘快照落后于最后一次合法状态。
新版只允许 running 导出，外部通知却发生在终止提交时，继续照抄旧回调中的 snapshot/flush 就已经太晚。

持久化宿主选择 captureSnapshotOnClose：退出决定全部通过后，仍在 running 的库导出一次并复核，然后终止，向宿主交付脱离实例的快照。
导出中的 save listener 若使批准/结构失效，保留会话；终止后的存储失败则报告已终止和未持久化两项事实，不能假装回滚退出。
同一 writer 停止旧节流工作后接收最后快照，防止旧写入覆盖它；没有启用、尚未启动完成或强制 dispose 时不额外导出。

**裁决：**最后导出的时点属于会话协调，存储与写入顺序属于宿主。[退出快照](worksplit-redesign.md#受保护退出的最后快照)拥有精确失败规则；不增加通用保存事务。对应 S06–S07。

## 四窗格可见读取与工具焦点

2×2 中四个选中页面都可能需要数据；打开问题面板后，文档仍可见但实际焦点属于工具。
当前 `read-visibility.tsx` 对每个内容订阅调用 getLayout，再由 `workbench-visibility.ts` 解析布局 JSON。
`financial-project-owner.ts` 的 revealTool 也重复展开、选择和最大化动作。这是库查询与揭示能力不足的直接消费者证据。

核心提供 `getContent(id).visible` 及位置投影，从真实原生选择、展开、Border 和最大化推导；所有入口复用 activate/reveal。
应用将 visible 与浏览器 visibility、页面内折叠组合成读取需求，交给既有 Query/RPC owner。
隐藏保留文档和草稿，但读取可暂停；工具移到中央仍是工具，获得焦点不改工作文档 URL。
“打开问题工具”和“展开底部区域”是两个应用动作，工具移动后不能把它们当同一件事。

**裁决：**增加一个有真实消费者的只读 visible 字段，删除下游快照查询路径；不增加数据调度器、可见性 registry 或面板管理平台。
对应[查询契约](worksplit-redesign.md#查询活动状态与焦点)、N10–N12、N13。

## 从预演得到的实现裁决

1. **公开边界保持小且完整。** 常用旁开、范围关闭、链接反馈、焦点和尝试期清理沿现有操作收拢；不把时序重新推给页面。
   ReadingLink、父层标记、业务 ID 选择、编辑修订继续在应用 owner 集中，不把它们注册成通用工作流。
2. **共享必要检查，保留不同完成点。** 所有关闭使用同一批准语义；Router、原生删除、业务写入和清理各自结算。
   统一结果不要求全局任务队列、公共 operation registry 或每个动作经过多层 service。
3. **预检只覆盖可证明的内容。** 简单操作直接读真实节点；确需拓扑预测时使用一次操作内的原生候选。
   不重放任意宿主 callback，不为反复查询建立长寿命候选缓存，不把零序列化写成零成本。
4. **历史适配覆盖实际提交边界。** 遍历、其他异步 blocker、无批准重载 redirect 都要验证；公开 backend 接口不自动解决完整关联与结算。
   保持唯一存储和原生解析/加载；公开能力不足时先确定可分发的最小上游修正。通过同一回归后才固定单一路径，后续等价能力成立再删除适配。
5. **以删除下游重复协调衡量价值。** 新版应删去菜单安全接线、布局 JSON 查询、重复工具揭示和重复批准循环；
   下游仍能直接使用 Router 与原生 Actions，业务语义没有被转移到库内。

## 实施时先证明什么

以下是架构成立的前置证据，不是本次已通过的新实现验收。完整矩阵仍在主提案。

代表路径还须带上本轮的全方向取舍：启动只有一个 owner，实例先选择再加载，导航决定和最终 history 提交分别核对，普通打开与焦点竞争分开。
标题、完整快照格式和包边界仍在各自消费者验证；不能用这些代表路径成功代替全部独立边界的验收。

| 次序 | 最小代表路径                                                                                                                                 | 能拒绝的错误架构                                                              |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 1    | 真实 Router 与唯一 history：五类导航、T1 在其他 blocker 等待而 T2 完成、无批准同址重载/invalidate redirect；真实拒绝结算和索引/通知正确      | 只修 GO、旧请求晚提交、ignoreBlocker 冒充批准、只结算库回执却挂起原生 Promise |
| 2    | history 已提交后慢 loader/redirect；T2 被拒绝不解除 T1 暂停；失败、取代、owner 隐藏、后台无 RouterProvider 和未进入 pending 均正确结算 defer | token 冒充最终提交保护；混淆物理位置/资源，永久或提前解冻                     |
| 3    | 普通 beside 与产品 resolver 共用旁开；B 筛选下探 C 后混用浏览器/页面返回，含同 href 不同 state、entry 截断、同 ID 重开                       | 双接纳路径、每层创建文档、用 URL/index 冒充历史项、浏览器遍历重复 push        |
| 4    | 2×2 加工具显隐：布局可见读取、默认及定制菜单/范围关闭、具体焦点请求和原生候选成本                                                            | 默认外观一改就复制保护；固定延迟焦点、布局快照查询/候选泛滥                   |
| 5    | 节流尚未保存时正常/外部退出、导出 listener 重入/抛错、终止后存储失败，以及 starting/force dispose                                            | 终止后才导出、以空布局覆盖偏好、存储失败伪装退出回滚、旧 writer 覆盖最后快照  |

用已批准的公开边界实现这些路径后，再扩展全部菜单、包和消费者迁移。某项上游能力若推翻契约，应在同一提案修订并保留反例；
不添加永久兼容路径，也不以未完成的运行能力宣布重构交付。
